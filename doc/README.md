# Documentation

The repository `README.md` introduces Diana, `CONTRIBUTING.md` is the setup and workflow guide,
and `spec/<method>.md` lists the theorems of each method. This directory holds the rest: the API,
what is verified and how, and the rationale that used to live in code comments.

## API

- [Overview](api/overview.md): headers, linking, status codes, the Python package, array arguments
- [Bisection](api/bisection.md)
- [Composite trapezoidal rule](api/trapezoidal.md)
- [Composite Simpson rule](api/simpson.md)
- [Explicit Euler step](api/euler.md)

## Verification

- [Trust statement](verification/trust.md): layers, trust base, where each layer is checked, the
  shipped binary, what is not verified
- [Report](verification/report.md): status of every theorem, generated by the spec gate
- [Spec gate](verification/spec-gate.md): `script/check_spec.py`
- [Frama-C and Flocq boundary](verification/frama-c.md): ACSL arithmetic, the `SKIP` list, goal
  counts
- [Floating-point helpers without libm](verification/fp.md): `src/fp.h`
- [Local verification](verification/local.md): the steps CI does not run, the Clight AST per
  target, the Rocq build
- [Compiler comparison](verification/compiler.md): `ccomp` against gcc and clang, bit for bit
