# Note

Technical notes: one fact, rule, procedure or rationale per file, named by a unique ID. They hold
the exact detail that `doc/` leaves out — evaluation order, check order, theorem coverage, tool
quirks, CI internals, test-value derivations — in a form an AI agent can find and cite. `doc/` is
written for human developers and links here for depth; `spec/<method>.md` stays the list of
theorems; `CLAUDE.md` is the condensed convention sheet.

## Find a note

- **Before editing a file**, look it up under [By path](#by-path): every note listed for it
  describes a rule or fact that the edit must keep true. `grep -rl 'src/rk4_step.c' note` finds
  the same notes.
- **To learn a topic**, pick its directory in the table below and read its section under
  [By topic](#by-topic); titles are one-line summaries.
- **To search**, `grep -ril '<keyword>' note`. To list every rule, `grep -rl '^kind: rule' note`.
- **To cite** a note, use its ID (`WP-002`), in a `doc/` page, another note's `related`, or a
  review comment. IDs are stable; a file path never needs to be guessed.

## Format

A note is `note/<topic>/<ID>.md` with YAML front matter and a short Markdown body:

```markdown
---
id: WP-002
title: No hexadecimal float literal in ACSL
kind: rule
path:
  - src/*_acsl.h
related: [WP-001]
---
The statement first, in one or two sentences; then detail, a reason or a check.
```

- `id`: `<PREFIX>-<NNN>`, the prefix the topic directory in capitals, three digits. It equals the
  file name.
- `title`: one line, at most 80 characters, no `|`.
- `kind`: `rule` (must or must not; says how it is enforced when it is), `fact` (how the code or
  tool behaves), `procedure` (numbered steps), or `rationale` (why a design is as it is).
- `path` (optional): repository paths or globs the note is about; each must match a file.
- `related` (optional): IDs of notes worth reading with this one.

The body states the current behaviour, with repository paths rather than line numbers, in 3 to 30
lines wrapped at 100 columns. It names theorem IDs (`BISECTION-C3`) where a proof backs a claim.

## Maintain

- A change that makes a note wrong updates the note in the same commit.
- A new note takes the next unused number of its topic. IDs are never renumbered or reused; an
  obsolete note is deleted and its ID retired.
- One subject per note: split a note that grows past about 30 lines.
- `uv run script/check_doc.py --write` regenerates the index below; without `--write` it fails on
  a stale index, a bad front matter field, a `path` that matches nothing, an unknown note ID, or a
  broken relative link anywhere in `README.md`, `CONTRIBUTING.md`, `CLAUDE.md`, `doc/`, `note/`
  or `spec/`.
  `script/dev.sh test` and the `style_python` CI job run it.
