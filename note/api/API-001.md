---
id: API-001
title: Runtime floating-point environment of every numerical call
kind: rule
path:
  - include/diana/diana.h
  - src/fp.h
related: [FP-003, FP-004, FP-005]
---
Every numerical call, from C or Python, requires on the calling thread IEEE binary64
round-to-nearest ties-to-even (`FE_TONEAREST`), gradual underflow (no flush-to-zero or
denormals-are-zero mode) and all floating-point traps disabled. Callbacks
(`diana_scalar_fn`, `diana_newton_fn`, `diana_ode_fn`, Python callables) must leave these
settings as they found them.

- Diana neither checks nor changes them: no file under `src/`, `include/` or `python/ext/`
  includes `<fenv.h>` or touches the rounding mode or trap masks.
- Compiler flags do not establish them. `-ffp-contract=off` and the `FLT_EVAL_METHOD == 0`
  assertion in `src/fp.h` fix the operation sequence at build time (FP-003, FP-004); the
  rounding mode, flush-to-zero and trap masks are run-time state of the thread.
- Under other settings no verified bound or stopping guarantee applies. The layer-B and VST
  theorems are stated for `mode_NE` with subnormals (the `η = 2⁻¹⁰⁷⁵` underflow terms, exact
  subnormal addition), and the stopping facts BISECTION-B3 and NEWTON-B3 are rounding facts.
- With traps enabled a call can trap before it returns a status: the kernels detect an error by
  computing the IEEE result and testing it, and `diana_fp_finite` itself evaluates `x - x`, an
  invalid operation for an infinite `x`.
