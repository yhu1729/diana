A kernel that returns `DIANA_ERR_ARG`, `DIANA_ERR_BRACKET`, `DIANA_ERR_SINGULAR` or
`DIANA_ERR_OVERFLOW` writes nothing, except `diana_cholesky` on `DIANA_ERR_SINGULAR`, the two
substitution kernels and `diana_lu_solve` on `DIANA_ERR_OVERFLOW`, and `diana_lu` on both; so
`DIANA_ERR_ARG` never writes. `DIANA_ERR_MAXITER` and the callback wrappers do write.

- `init` and `step` leave `*s` unchanged on `DIANA_ERR_ARG` and `DIANA_ERR_BRACKET` (bisection:
  BISECTION-C2, C3, C8, C9) and on `DIANA_ERR_ARG`, `DIANA_ERR_SINGULAR` and
  `DIANA_ERR_OVERFLOW` (Newton: NEWTON-C1, C2, C5, C6), so the caller may retry `step`.
- A `step` that returns `DIANA_ERR_MAXITER` has done the whole step: bisection has halved the
  bracket and incremented `iter`, Newton has stored the new `x`, `dx` and `iter`. `*_result`
  then reports the estimate reached.
- `diana_bisection_result` and `diana_newton_result` with a NULL `s` return `DIANA_ERR_ARG` and
  write neither output.
- The array kernels leave `*result` or `y_out[0 .. d-1]` untouched on `DIANA_ERR_ARG` and
  `DIANA_ERR_OVERFLOW` (TRAPEZOIDAL-C1, SIMPSON-C1, EULER-C1, RK4-C1, RK4-C2; the unchecked ones,
  whose only error is `DIANA_ERR_ARG`: EULER-UNCHECKED-C1, RK4-UNCHECKED-C1, C2). The checked ones
  test every component before writing any (KERNEL-002), so a failure in the last component also
  leaves the output as it was.
- `diana_cholesky` leaves `l` untouched on `DIANA_ERR_ARG` (CHOLESKY-C1, C3) but has already
  written part of `l` when it finds a pivot that is not positive: each column needs the columns
  before it, so no check can come first. The contents are unspecified after
  `DIANA_ERR_SINGULAR` (API-028).
- `diana_forward_substitution` and `diana_back_substitution` leave `x` untouched on a non-finite
  input and on `DIANA_ERR_SINGULAR` (SUBSTITUTION-C1 to C4), but an entry that overflows is found
  only after the entries before it are written: `DIANA_ERR_OVERFLOW` then leaves `x` partly
  written, contents unspecified (API-030).
- `diana_lu` leaves `lu` and `piv` untouched on a non-finite entry of `a` (LU-C1, C2), but it
  copies `a` to `lu` before the first step, so a zero pivot column (`DIANA_ERR_SINGULAR`) or an
  overflowing update (`DIANA_ERR_OVERFLOW`) is found with both partly written, contents unspecified
  (API-032).
- `diana_lu_solve` leaves `x` untouched on a non-finite entry of `lu` or `b`, a pivot row
  `piv[k] >= n` and `DIANA_ERR_SINGULAR` (LU-SOLVE-C1, C2), but it copies `b` to `x` and solves
  in place, so an entry of either solve that overflows (`DIANA_ERR_OVERFLOW`) is found with `x`
  partly written, contents unspecified (API-034).
- The wrappers write their count on every return: `*iter` or `*done` (optional) is set to 0
  first, then to the number of completed steps. `diana_bisection` and `diana_newton` write
  `*root` only on `DIANA_OK` and `DIANA_ERR_MAXITER`. `diana_euler` and `diana_rk4` copy each
  completed step into `y`, so after a failed step `y` holds the state of the last completed one
  and `*done` counts the completed steps.
- Python: an exception from `Bisection` or `Newton` leaves the state and `status` as they were
  (API-023). `diana.euler` and `diana.rk4` raise without returning the partial state.
