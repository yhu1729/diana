id: API-003
title: What a failed call writes
kind: fact
path:
  - src/*.c
  - python/src/diana/_euler.py
  - python/src/diana/_rk4.py
related: [API-002, API-006, KERNEL-002]

A kernel that returns `DIANA_ERR_ARG`, `DIANA_ERR_BRACKET` or `DIANA_ERR_SINGULAR` writes
nothing. `DIANA_ERR_MAXITER` and the callback wrappers do write.

- `init` and `step` leave `*s` unchanged on `DIANA_ERR_ARG` and `DIANA_ERR_BRACKET` (bisection:
  BISECTION-C2, C3, C8, C9) and on `DIANA_ERR_ARG` and `DIANA_ERR_SINGULAR` (Newton: NEWTON-C1,
  C2, C5, C6), so the caller may retry `step` with a corrected value.
- A `step` that returns `DIANA_ERR_MAXITER` has done the whole step: bisection has halved the
  bracket and incremented `iter`, Newton has stored the new `x`, `dx` and `iter`. `*_result`
  then reports the estimate reached.
- `diana_bisection_result` and `diana_newton_result` with a NULL `s` return `DIANA_ERR_ARG` and
  write neither output.
- The array kernels leave `*result` or `y_out[0 .. d-1]` untouched on `DIANA_ERR_ARG`
  (TRAPEZOIDAL-C1, SIMPSON-C1, EULER-C1, RK4-C1, RK4-C2, EULER-UNCHECKED-C1, RK4-UNCHECKED-C1,
  RK4-UNCHECKED-C2). The checked ones test every component before writing any (KERNEL-002), so
  a failure in the last component also leaves the output as it was.
- The wrappers write their count on every return: `*iter` or `*done` (optional) is set to 0
  first, then to the number of completed steps. `diana_bisection` and `diana_newton` write
  `*root` only on `DIANA_OK` and `DIANA_ERR_MAXITER`. `diana_euler` and `diana_rk4` copy each
  completed step into `y`, so after a failed step `y` holds the state of the last completed one
  and `*done` counts the completed steps.
- Python: an exception from `Bisection` or `Newton` leaves the state and `status` as they were
  (API-023). `diana.euler` and `diana.rk4` raise without returning the partial state.
