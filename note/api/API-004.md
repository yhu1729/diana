An output must not overlap any input or another output; inputs, which are only read, may overlap
each other. `diana_axpy` is the one kernel whose output `y` is also an input, read before it is
written. In C these are ACSL `\separated` preconditions, not run-time checks: a call that
breaks one is outside every contract and theorem.

- `diana_bisection_result(s, root, width)`, `diana_newton_result(s, root, dx)`: each output may
  be NULL and is then skipped; a non-NULL one must be valid and separate from `*s` and from the
  other output.
- `diana_trapezoidal`, `diana_simpson`: `result` is required (NULL is `DIANA_ERR_ARG`) and must
  not overlap `y[0 .. n-1]`; likewise `result` of `diana_norm_1`, `diana_norm_2` and
  `diana_norm_inf` and `x[0 .. n-1]`.
- `diana_cholesky`: `l[0 .. n*n-1]` must not overlap `a[0 .. n*n-1]`; both are required (NULL
  is `DIANA_ERR_ARG`). The kernel reads back the entries of `l` it has written.
- `diana_forward_substitution`, `diana_transpose_substitution`: `x[0 .. n-1]` must not overlap
  `l[0 .. n*n-1]` or `b[0 .. n-1]` (all required); the solve reads back entries of `x`, so no
  in-place solve with `x == b`. `l` and `b` may overlap for WP (SUBSTITUTION-C1, C2), but the VST
  funspecs hold a separate `data_at` per array (SUBSTITUTION-C3, C4). Solving `A·x = b` therefore
  takes two vectors: forward from `b` into `y`, back from `y` into `b`.
- `diana_lu`: `lu[0 .. n*n-1]` and `piv[0 .. n-1]` must not overlap `a[0 .. n*n-1]` or each
  other (all required, LU-C1); the kernel works in place in `lu` after copying `a` into it.
- `diana_lu_solve`: `x[0 .. n-1]` must not overlap `lu[0 .. n*n-1]`, `piv[0 .. n-1]` or
  `b[0 .. n-1]` (all required, LU-SOLVE-C1); the kernel copies `b` into `x` and solves in place,
  so no `x == b`. The inputs may overlap for WP; the VST funspec holds a separate `data_at` per
  array (LU-SOLVE-C2).
- `diana_euler_step`, `diana_rk4_stage`, `diana_rk4_step` and their `_unchecked` variants:
  `y_out[0 .. d-1]` must not overlap `y` or any slope (`f`, `k`, `k1` to `k4`), so a time loop
  alternates two buffers. Overlapping inputs are covered by WP for memory safety (EULER-C1,
  RK4-C1, RK4-C2), but every VST funspec holds a separate `data_at` per array, so the value
  theorems (EULER-C2, RK4-C3, RK4-C4 and the unchecked ones) assume disjoint inputs.
- `diana_axpy`: `y[0 .. n-1]` must not overlap `x[0 .. n-1]` (both required, AXPY-C1); the
  kernel reads each `y[i]` and writes it back in the same iteration, so `x == y` or a shifted
  overlap would change what the second pass reads. The VST funspec holds a separate `data_at`
  per array (AXPY-C2).
- `diana_euler`, `diana_rk4`: `work` (`lwork` doubles, at least `2*d` or `5*d`) must not overlap
  `y`; the wrappers split `work` into disjoint slices themselves. `root` of `diana_bisection` and
  `diana_newton` is required; `iter` and `done` may be NULL.
- The public Python functions take no output argument, except `diana.axpy`, whose `y` is the
  writable buffer it updates in place: the vector ones return a fresh `array.array("d")`. The
  extension functions behind them (`diana._diana.euler_step`, `rk4_stage`, `rk4_step`) take an
  explicit writable `out`, and `diana._diana.axpy` its `y`, and check at run time that it
  overlaps no input (`diana_py_overlap` in `python/ext/module.h`, `ValueError`, API-040).
