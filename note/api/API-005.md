An installed Diana is found with `find_package(diana <version> CONFIG REQUIRED)` and linked
through the imported target `diana::diana`, which carries the include directory.

- `cmake --install` writes `dianaTargets.cmake` (export `dianaTargets`, namespace `diana::`),
  `dianaConfig.cmake` and `dianaConfigVersion.cmake` to `<libdir>/cmake/diana`, the headers to
  `<includedir>/diana` and the library to `<libdir>`; a consumer sets `CMAKE_PREFIX_PATH` to the
  prefix. In the build tree `diana::diana` is an `ALIAS` of `diana`.
- Compatibility is `SameMinorVersion`, set unconditionally in `CMakeLists.txt`: a request for
  `1.0` accepts any 1.0.x, never 1.1 or 2.0. It was the same in the 0.x series.
- The library is static unless `DIANA_BUILD_SHARED_LIB=ON`. Standalone builds set `VERSION` and
  `SOVERSION` (the major version). A `DIANA_SANITIZER` build links `-fsanitize=address,undefined`
  as a public option, so the installed target passes it to consumers.
- Under scikit-build (`SKBUILD` defined) the install and export rules are skipped: a wheel
  carries no CMake package.
- With `DIANA_BUILD_TEST=ON`, the ctests `install` and `find_package` install into the build tree
  and build `test/install/` against it; that consumer runs `diana_bisection` and checks
  `diana_version()` against `DIANA_VERSION_STRING`.
