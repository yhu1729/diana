title: Bisection wrapper evaluation order and outputs
kind: fact
path:

  - test/c/test_bisection.c

---
`diana_bisection(f, ctx, a, b, tol, max_iter, root, iter)` evaluates `f(a)`, then `f(b)`, then
`f` once per step, so a successful run calls `f` exactly `iter + 2` times
(`test_evaluation_count`, `test_evaluation_order` in `test/c/test_bisection.c`).

1. `*iter = 0` if `iter` is non-NULL.
2. `f` or `root` NULL: `DIANA_ERR_ARG`, `f` not called.
3. `fa = f(a, ctx)`, `fb = f(b, ctx)`, before any check of `a`, `b`, `tol` or `max_iter`:
   `diana_bisection_init` validates them afterwards, so `f` is called even when the arguments
   are rejected. An init error (`DIANA_ERR_ARG`, including a non-finite `f(a)` or `f(b)`, or
   `DIANA_ERR_BRACKET`) returns with `*iter = 0` and `*root` unwritten.
4. While the status is `DIANA_CONTINUE`: `diana_bisection_step(&s, f(s.x, ctx))`.
5. `*iter = s.iter`, the completed steps (a step rejected for a non-finite `f(x)` is not counted).
6. `DIANA_ERR_ARG` from a step returns without writing `*root`. On `DIANA_OK` or
   `DIANA_ERR_MAXITER`, `*root = 0.5 * (a + b)` of the final bracket (via
   `diana_bisection_result`), then that status is returned.

`a` and `b` reach `f` exactly as passed. The callback result must be finite; there is no other
error channel (API-006).
