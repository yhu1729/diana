With `tol = 0`, Newton's method in binary64 near a simple root commonly never meets a stopping
test: the iterate alternates between two adjacent doubles and only `max_iter` ends the run, with
`DIANA_ERR_MAXITER`. Hence the Python API takes `tol` without a default.

- On `f(x) = x² − 2`, `f′(x) = 2x` from `x₀ = 2` (evaluated in binary64, no FMA), step 5 reaches
  `1.4142135623730951`, the correctly rounded √2. There the computed `f` is `2⁻⁵¹`, not 0, and
  `dx ≈ 1.57e-16`, about 0.71 ulp of `x`: more than the half ulp of the stagnation stop
  (NEWTON-B3), so step 6 moves to the lower neighbour `1.4142135623730949`, step 7 back, and so
  on.
- `test_two_cycle` (`test/c/test_newton.c`) pins that every iterate after step 6 is one of the
  two doubles and that 100 steps end in `DIANA_ERR_MAXITER` at the lower one;
  `test_two_cycle_at_zero_tol` (`test/python/test_newton.py`) pins the Python `MaxIterError`.
- The C API keeps `tol = 0` legal (a fixed point of the binary64 map is a valid request); the
  Python `Newton` and `newton` make the caller choose a tolerance. Their default
  `max_iter = 100` is a safety limit, not a convergence guarantee.
- No theorem bounds the binary64 step count or proves convergence in binary64 (PROOF-002).
