`diana_trapezoidal(y, n, h, result)` evaluates, in binary64 and in this order,
`s = 0.5 * (y[0] + y[n-1])`, then `s = s + y[i]` for `i = 1, ..., n-2`, then `r = h * s`, and
checks only `r`.

1. `y` NULL, `result` NULL or `n < 2`: `DIANA_ERR_ARG`; nothing is read or written.
2. Compute `r` as above (`n == 2` skips the loop).
3. `r` NaN or ±∞: `DIANA_ERR_ARG`, `*result` unchanged. Otherwise `*result = r`, `DIANA_OK`.

- A NaN or infinite sample or `h`, or an overflow in any operation, makes `r` non-finite (an
  infinite `h` against `s == 0`, or `h == 0` against an infinite `s`, gives NaN). Conversely a
  finite `r` certifies every sample, partial sum and operation finite (TRAPEZOIDAL-B1), which is
  why checking `r` alone suffices.
- `h` may be negative (integration in the opposite direction) or zero. The `n - 1` panels have
  width `h`; the kernel never sees the abscissae.
- `y[0 .. n-1]` is only read and must not overlap `*result` (API-004).
- Each operation is rounded separately (`-ffp-contract=off`): `0.5 * (...)` can be inexact only
  when its result is subnormal (error at most `2⁻¹⁰⁷⁵`), and the sum runs left to right,
  uncompensated.
