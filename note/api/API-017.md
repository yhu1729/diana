`diana_euler(fn, ctx, t0, h, nstep, y, d, work, done)` and `diana_rk4(...)` (same parameters)
take `nstep` steps of size `h` from `y(t0) = y[0 .. d-1]`, in place, with
`fn(t, y, dy, d, ctx)` writing `F(t, y)` to `dy[0 .. d-1]`.

- Checks: `*done = 0` (if non-NULL); `fn`, `y` or `work` NULL, or `d == 0`: `DIANA_ERR_ARG`
  without calling `fn`. `nstep == 0` then returns `DIANA_OK` with `y` unchanged. `t0` and `h`
  are not checked; a non-finite `h` fails the first step.
- Times come from the step index `k`, never accumulated: Euler evaluates at `t0 + (double)k * h`;
  RK4 at `t0 + (double)k * h`, `t0 + ((double)k + 0.5) * h` (twice) and
  `t0 + (double)(k + 1) * h`, each product rounded before the sum.
- `work`: Euler uses `2*d` doubles (the slope, then the next state); RK4 uses `5*d` (`k1` to
  `k4`, then the stage point, which also receives the new state). It must not overlap `y` and
  is not initialised, so `fn` must write every `dy[i]`.
- RK4 step `k`: `fn(t, y, k1)`, stage 2 into the stage point, `fn(t + h/2, ., k2)`, stage 3,
  `fn(t + h/2, ., k3)`, stage 4, `fn(t + h, ., k4)`, then `diana_rk4_step` (API-016).
- A failed stage or step returns its status at once, `DIANA_ERR_ARG` for a non-finite slope,
  state or `h`, and `DIANA_ERR_OVERFLOW` for an overflow of finite values: `y` holds the state
  after the last completed step and `*done` counts the completed steps. After each completed
  step `y` is overwritten and `*done = k + 1`.
- `test_wrapper_failure` in `test/c/test_euler.c` and `test/c/test_rk4.c` pins the partial
  progress: on `y′ = t` from `0` with `h = 1`, `fn` returning ∞ on its third call leaves
  `*done == 2` and `y == 1` (Euler).
