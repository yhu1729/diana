The checked kernels are the default. Use an `_unchecked` kernel only where the caller checks the
state itself, or need not stop at the first non-finite component, and the kernel is a measured
cost: the saving is a fraction of a nanosecond per component on the machines measured so far.

- Why it is faster: one pass with no branch, which the compilers vectorize; the checked kernels
  make two passes and can return at the first non-finite component (KERNEL-002).
- Measure it: `DIANA_BENCHMARK_CASE="euler rk4" script/benchmark.sh` prints, for each kernel,
  the checked and the unchecked row at `d` = 64, 1024 and 16384 (ns per component, in-cache
  data), and the `euler_loop` and `rk4_loop` rows, a whole step with the cheapest right-hand side
  `dy[i] = -0.5 * y[i]`, checked and unchecked (BENCHMARK-005). No figure is recorded in the
  repository (BENCHMARK-002); on the development machines the kernels alone have run a few times
  faster unchecked, a saving of a fraction of a nanosecond per component.
- So the gain matters only when the right-hand side costs well under a few nanoseconds per
  component: compare the `_loop` rows with a right-hand side like yours before choosing.
- Checking afterwards is exact: a finiteness test of `y_out` after the call rejects exactly what
  the checked kernel would (API-018).
