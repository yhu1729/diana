A real-valued argument accepts any object whose type has `__float__` or `__index__` (`int`,
`bool`, `Fraction`, `Decimal`, ...) and is converted to the nearest double before the kernel
sees it; a `str` is rejected with `TypeError`, never parsed.

- In the extension the CPython `d` converter does this (`h`, `x0`, `tol`, `a`, `b`, `fa`, `fb`
  and the `step` arguments): `TypeError: must be real number, not str`.
- The drivers use `real(x, name)` (`python/src/diana/_convert.py`): it checks the type for
  `__float__` or `__index__`, then calls `float(x)`, so the message names the argument (`a must
  be a real number, not str`). `diana.bisection` applies it to `a`, `b`, `tol` and every value of
  `f`; `diana.euler` and `diana.rk4` to `t0` and `h`. `diana.newton` passes `x0`, `tol` and the
  pair from `f` to the extension unconverted.
- `max_iter` (`Bisection`, `Newton`, `bisection`, `newton`) goes through
  `diana_py_convert_uint`: `operator.index` semantics, so `2.0` is `TypeError`; a negative value
  or one above `UINT_MAX` is `OverflowError`; 0 converts, and the C `init` rejects it with
  `ValueError: invalid argument`.
- `stage` of `rk4_stage` uses the C `int` converter: non-integer `TypeError`, outside the C `int`
  range `OverflowError` (`2**40`), then `ValueError: stage must be 2, 3 or 4`.
- `nstep` of `euler` and `rk4`: `operator.index` (`TypeError`), negative `ValueError`, no upper
  bound.
- `status_str(code)` takes an integer (`__index__`), else `TypeError`; outside C `long` or C
  `int`, `OverflowError`.
