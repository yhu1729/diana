A C error status becomes an exception through `diana_py_raise` (`python/ext/raise.c`):
`DIANA_ERR_ARG` raises `ValueError`, `DIANA_ERR_BRACKET` `diana.BracketError`,
`DIANA_ERR_SINGULAR` `diana.SingularError`, `DIANA_ERR_OVERFLOW` `diana.FloatOverflowError`. The
three are created in C (`python/ext/status_exec.c`, qualified names `diana._diana.BracketError`,
`diana._diana.SingularError`, `diana._diana.FloatOverflowError`) and re-exported by `diana`; the
first two subclass `ValueError`, the third both `ValueError` and `OverflowError`, so code that
catches `ValueError` catches it too. It is not named `OverflowError` so that
`from diana import *` cannot shadow the built-in. Any other status would map to `RuntimeError`;
no caller passes one.

- Messages: `init` errors use `diana_status_str` (`invalid argument`, `no sign change in bracket`);
  array kernels say `<name> input is not finite: <inputs>` or `<name> result overflows`, with
  `<name>` `trapezoidal`, `Simpson`, `Euler step`, `RK4 stage`, `RK4 step`, `axpy` and `<inputs>`
  `a sample or h`, `y, f or h`, `y, k or h`, `y, a slope or h`, `a, x or y`; `cholesky`, the substitution
  functions, `lu` and `lu_solve` name the cause (API-029, API-031, API-033, API-035); the norms
  say `x has a non-finite entry` or `the norm overflows` (API-038);
  `Bisection.step` says `f(x) must be finite`; `Newton.step` says `f(x) and f'(x) must be
  finite`, `Newton step overflows` (correction or iterate) or `f'(x) is zero`.
- `DIANA_ERR_MAXITER` is returned as a status by `Bisection.step` and `Newton.step`. Only the
  drivers `diana.bisection` and `diana.newton` raise `diana.MaxIterError`, a pure-Python
  `RuntimeError` subclass (`python/src/diana/_error.py`) with `estimate` (the `result()` root),
  `uncertainty` (bisection: bracket width `b - a`; Newton: `|dx|`) and `iter` (steps taken).
  `args` is `(estimate, uncertainty, iter)`, so it survives pickling; `str()` is
  `iteration limit <iter> reached; estimate <estimate!r>, uncertainty <uncertainty!r>`.
- `RuntimeError` from the state objects: `<Type> state is not initialized` (`step` or `result`
  before a successful `__init__`) and `step called on a finished <Type> state` (API-023).
- Argument errors are `TypeError`, `OverflowError` (API-021) or `TypeError`, `ValueError`
  (API-020). `diana.newton` unpacks `f(x)` as a pair: a scalar raises `TypeError`, a sequence
  of another length `ValueError`, both from Python's unpacking.
