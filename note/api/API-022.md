A C error status becomes an exception through `diana_py_raise` (`python/ext/raise.c`):
`DIANA_ERR_ARG` raises `ValueError`, `DIANA_ERR_BRACKET` `diana.BracketError`,
`DIANA_ERR_SINGULAR` `diana.SingularError`. Both are `ValueError` subclasses created in C
(`python/ext/status_exec.c`, qualified names `diana._diana.BracketError` and
`diana._diana.SingularError`) and re-exported by `diana`. Any other status would map to
`RuntimeError`; no caller passes one.

- Messages: `init` errors use `diana_status_str` (`invalid argument`, `no sign change in
  bracket`); array kernels name the result (`trapezoidal result is not finite`, `Simpson result
  is not finite`, `Euler step result is not finite`, `RK4 stage result is not finite`, `RK4 step
  result is not finite`); `cholesky`, the substitution functions and `lu` name the cause
  (API-029, API-031, API-033); `Bisection.step` says `f(x) must be finite`; `Newton.step` says
  `f(x) and f'(x) must be finite`, `Newton step is not finite` (overflowing correction or
  iterate) or `f'(x) is zero`.
- `DIANA_ERR_MAXITER` is returned as a status by `Bisection.step` and `Newton.step`. Only the
  drivers `diana.bisection` and `diana.newton` raise `diana.MaxIterError`, a pure-Python
  `RuntimeError` subclass (`python/src/diana/_error.py`) with `estimate` (the `result()` root),
  `uncertainty` (bisection: bracket width `b - a`; Newton: `|dx|`) and `iter` (steps taken).
  `args` is `(estimate, uncertainty, iter)`, so it survives pickling; `str()` is
  `iteration limit <iter> reached; estimate <estimate!r>, uncertainty <uncertainty!r>`.
- `RuntimeError` from the state objects: `<Type> state is not initialized` (`step` or `result`
  before a successful `__init__`) and `step called on a finished <Type> state` (API-023).
- Argument errors are `TypeError`, `OverflowError` (API-021) or `TypeError`, `ValueError`
  (API-020). `diana.newton` unpacks `f(x)` as a pair: a scalar raises `TypeError`, a sequence
  of another length `ValueError`, both from Python's unpacking.
