`diana.bisection` and `diana.Bisection` default to `tol = 0`, the finest answer binary64 allows,
and `max_iter = 2100`, which the worst case of `tol = 0` never reaches, so with default
arguments `MaxIterError` is not expected.

- `tol = 0` never meets `b - a <= tol` until the bracket collapses, so a run stops at an exact
  zero of `f` or when the binary64 midpoint equals an endpoint, which BISECTION-B3 guarantees
  once the endpoints are adjacent doubles. The answer is then `0.5 * (a + b)` of that last
  bracket.
- 2100 covers the measured worst case of 2098 steps: a root at `DBL_TRUE_MIN` in
  `[-DBL_MAX/2, DBL_MAX/2]`, pinned by `test_worst_case_step_count` (`test/c/test_bisection.c`)
  and `test_default_max_iter_worst_case` (`test/python/test_bisection.py`). The constant is not
  a theorem: BISECTION-B4 proves termination with the loose bound `n <= lattice`, and the
  closed form `emax - emin + p + 1 = 2098` comes from exhaustive search over small binary
  formats ("What B4 does not say" in `spec/bisection.md`).
- `a` and `b` are converted to `float` before `f` is called, so `f(a)` and `f(b)` are the
  values at the binary64 endpoints the kernel brackets (`test_callback_sees_kernel_endpoint`).
- `f` is evaluated once at each endpoint, then once per step; there is no evaluation cache.
