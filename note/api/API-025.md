`diana.newton(f, x0, tol, max_iter=100)` and `diana.Newton(x0, tol, max_iter=100)` require
`tol`: Newton's method has no parameter-free stopping rule, and `tol = 0` commonly ends in a
two-cycle of adjacent doubles that only `max_iter` stops (API-011). Omitting it is `TypeError`
(`test_tol_required`).

- `max_iter = 100` is a safety limit, not a convergence guarantee; `MaxIterError` then carries
  the current iterate and `|dx|`.
- `f(x)` returns the pair `(f(x), f′(x))`, unpacked as `fx, dfx = f(state.x)`: a scalar
  return raises `TypeError` and a sequence of another length `ValueError`, both from the
  unpacking. Both values are converted by the extension's `d` converter (API-021).
- The loop stops on `|dx| <= tol`, on a correction too small to change `x`, or on
  `f(x) == 0`. A zero `f′(x)` raises `SingularError` only when `f(x)` is finite and non-zero; a
  non-finite value raises `ValueError`, and a correction or iterate that overflows
  `FloatOverflowError` (also a `ValueError`). Each leaves the state at the last iterate, but the
  driver does not expose it.
- `f` is called once per step with `state.x`, a `float`; the driver keeps no other state and
  runs no check of its own beyond the extension's.
