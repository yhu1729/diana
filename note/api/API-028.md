`diana_cholesky(a, n, l)` (`src/cholesky.c`) factors the `n×n` matrix stored column-major,
`a[i + j*n] = A[i, j]`, into `l` in the same layout. Exits in order:

1. `a` NULL, `l` NULL, `n == 0`, or `n > (size_t)-1 / n` (so `n*n` would wrap): `DIANA_ERR_ARG`,
   nothing read or written.
2. Validation, column `j = 0, …, n-1`, row `i = j, …, n-1`: the first `a[i + j*n]` that
   `diana_fp_finite` rejects returns `DIANA_ERR_ARG` with `l` untouched (CHOLESKY-C1, C3). The
   strict upper triangle of `a` is never read, so a NaN there is accepted.
3. Column `j`: `l[i + j*n] = +0` for `i < j`; `s = a[j + j*n]`, then
   `s = s - l[j + k*n] * l[j + k*n]` for `k = 0, …, j-1`, the product rounded first;
   `if (!(s > 0.0))` returns `DIANA_ERR_SINGULAR`, for a negative, ±0 or NaN pivot alike;
   `d = diana_fp_sqrt(s)` and `l[j + j*n] = d`; for `i = j+1, …, n-1`, `s = a[i + j*n]`, the
   subtractions with `l[i + k*n] * l[j + k*n]`, and `l[i + j*n] = s / d`, a division rather than
   a product with `1/d`.
4. `DIANA_OK`.

- Every write goes to the next linear index `i + j*n`. On `DIANA_ERR_SINGULAR` at column `j`,
  `l[0 .. j*n + j - 1]` holds the model factor and the rest is as the caller left it, but the
  API calls the contents unspecified and VST proves only their length (CHOLESKY-C3).
- No check of the output: on `DIANA_OK` every entry is finite (CHOLESKY-B2), because a
  non-finite entry below the diagonal makes a later pivot `-inf` or NaN.
- The inner sums read entries of `l` written earlier, so `l` must not overlap `a` (API-004).
