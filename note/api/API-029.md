`diana.cholesky(a)` copies a non-buffer `a` into `array.array("d")` (API-020), allocates a zeroed
`array.array("d")` of the same byte length, calls `diana._diana.cholesky(a, out)` and returns
`out`, the factor in the column-major layout of `a`, strict upper triangle zero.

Check order in the extension (`python/ext/cholesky.c`):
1. argument parsing (`a`, `out`, positional or keyword);
2. `diana_py_get_array` on `a`, minimum length 1 (`a must have at least one sample`), then on
   `out` (writable: a read-only exporter raises `BufferError`);
3. `n`, the largest integer with `n*n <= len(a)` (`diana_py_square_side` in
   `python/ext/module.h`, a loop that never overflows);
   `n*n != len(a)` raises `ValueError` (`a must have n*n samples for some n, a square number`);
4. `len(out) != len(a)`: `ValueError` (`out must have the same length as a`);
5. overlap of `out` and `a`: `ValueError` (`out must not overlap a`);
6. the kernel: `DIANA_ERR_ARG` raises `ValueError` (`a has a non-finite entry on or below the
   diagonal`) with `out` untouched; `DIANA_ERR_SINGULAR` raises `diana.SingularError`
   (`matrix is not positive definite: a pivot is not positive`) with `out` possibly written,
   which the public function discards.

With NumPy: `diana.cholesky(A.ravel(order="F"))`, then `np.asarray(L).reshape(n, n, order="F")`;
for a symmetric `A`, `A.ravel()` gives the same list. The public function takes no `n`: it is
inferred from the length.
