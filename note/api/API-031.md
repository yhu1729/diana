`diana.forward_substitution(lower, b)` and `diana.transpose_substitution(lower, b)` copy a
non-buffer argument into `array.array("d")` (API-020), allocate a zeroed `array.array("d")` of the
byte length of `b`, call `diana._diana.forward_substitution(lower, b, out)` (or `back_…`) and return
`out`. The parameter is `lower`, not `l` as in C, because ruff's E741 rejects the name `l`.

Check order in the shared extension helper `diana_py_substitution` (`python/ext/substitution.c`;
`forward_substitution.c` and `transpose_substitution.c` pass it their kernel and format string):
1. argument parsing (`lower`, `b`, `out`, positional or keyword);
2. `diana_py_get_array` on `lower` (`lower must have at least one sample`), `b` (`b must have at
   least one sample`), then `out` (writable: a read-only exporter raises `BufferError`);
3. `len(lower) != len(b)**2`: `ValueError` (`lower must have n*n samples, n the length of b`);
4. `len(out) != len(b)`: `ValueError` (`out must have the same length as b`);
5. overlap of `out` with `lower` or `b`: `ValueError` (`out must not overlap lower or b`);
6. the kernel: `DIANA_ERR_ARG` raises `ValueError` (`lower or b has a non-finite entry`),
   `DIANA_ERR_OVERFLOW` `diana.FloatOverflowError` (`the solution overflows`) and
   `DIANA_ERR_SINGULAR` `diana.SingularError` (`matrix is singular: a diagonal entry is zero`).
   `out` is untouched after a non-finite entry or a zero diagonal and possibly written after an
   overflow, which the public functions never return.

With NumPy: `forward_substitution(L.ravel(order="F"), b)`; the result of `diana.cholesky` goes in as
it is, so `transpose_substitution(F, forward_substitution(F, b))` with `F = diana.cholesky(a)`
solves `A·x = b`.
