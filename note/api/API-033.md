`diana.lu(a)` copies a non-buffer `a` into `array.array("d")` (API-020), allocates a zeroed
`array.array("d")` of the same byte length, calls `diana._diana.lu(a, out)` and returns
`(out, piv)`: the packed factor in the column-major layout of `a`, and the pivot rows as a `list`
of `int`.

Check order in the extension (`python/ext/lu.c`):
1. argument parsing (`a`, `out`, positional or keyword);
2. `diana_py_get_array` on `a`, minimum length 1, then on `out` (writable: a read-only exporter
   raises `BufferError`);
3. `n = diana_py_square_side(len(a))`; `n*n != len(a)` raises `ValueError` (`a must have n*n
   samples for some n, a square number`);
4. `len(out) != len(a)`: `ValueError` (`out must have the same length as a`);
5. overlap of `out` and `a`: `ValueError` (`out must not overlap a`);
6. `PyMem_New(size_t, n)` for the pivots, `MemoryError` if it fails, freed on every return;
7. the kernel: `DIANA_ERR_ARG` raises `ValueError` (`a has a non-finite entry, or an update
   overflows`), with `out` untouched for a non-finite entry and possibly written after an
   overflow; `DIANA_ERR_SINGULAR` raises `diana.SingularError` (`matrix is singular: a pivot
   column is zero`) with `out` possibly written. The public function returns neither;
8. the pivots as a new list of `int` (`PyLong_FromSize_t`).

With NumPy: `diana.lu(A.ravel(order="F"))`, then `F = np.asarray(lu).reshape(n, n, order="F")`,
`L = np.tril(F, -1) + np.eye(n)` and `U = np.triu(F)`; swapping `rows[k]` and `rows[piv[k]]` for
`k = 0, 1, …` in `rows = list(range(n))` gives `A[rows] = L @ U` up to rounding.
