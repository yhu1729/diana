`diana.lu_solve(lu, piv, b)` copies a non-buffer `lu` or `b` into `array.array("d")` (API-020),
allocates a zeroed `array.array("d")` of the byte length of `b`, calls
`diana._diana.lu_solve(lu, piv, b, out)` and returns `out`; `piv` goes to the extension as it is.
So `diana.lu_solve(*diana.lu(a), b)` solves `A·x = b`.

Check order in the extension (`python/ext/lu_solve.c`):
1. argument parsing (`lu`, `piv`, `b`, `out`, positional or keyword);
2. `diana_py_get_array` on `lu` (`lu must have at least one sample`), `b`, then `out` (writable);
3. `len(lu) != len(b)**2`: `ValueError` (`lu must have n*n samples, n the length of b`);
4. `len(out) != len(b)`, then overlap of `out` with `lu` or `b`: `ValueError`;
5. `PyObject_GetIter(piv)`: any iterable (a list, a tuple, a NumPy array, a generator), else
   `TypeError` (`piv must be an iterable of int`); `PySequence_Tuple` then copies its items into a
   new tuple, and a length other than `len(b)` is `ValueError`. Not `PySequence_Fast`, which
   returns a list argument itself: step 6 runs `__index__`, which could shrink the list under
   the loop. The solve uses the items `piv` held before step 6;
6. `PyMem_New(size_t, n)` (`MemoryError`, freed on every return), then each item through
   `operator.index` and `PyLong_AsSize_t`: `TypeError` for a float or a string, `OverflowError`
   for a negative value or one above `SIZE_MAX`;
7. the kernel: `DIANA_ERR_ARG` raises `ValueError` (`lu or b has a non-finite entry, a pivot row
   is not below n, or the solution overflows`), `DIANA_ERR_SINGULAR` raises
   `diana.SingularError` (`matrix is singular: a diagonal entry of U is zero`). `out` is
   untouched after the validation exits and possibly written after an overflow, which the public
   function never returns.

A factor from `diana.lu` never has a zero diagonal entry, so `SingularError` needs a factor built
by other means.
