title: Non-finite input versus overflow, classified only on the error path
kind: fact
path:

  - src/rk4_stage.c

`diana_euler_step`, `diana_rk4_stage`, `diana_rk4_step`, `diana_trapezoidal` and
`diana_simpson` return `DIANA_ERR_ARG` when an input is NaN or ±∞ and `DIANA_ERR_OVERFLOW` when
every input is finite but a computed value is not. The check pass computes each component (or
the one result) and tests it with `diana_fp_finite`; only at the first failure does it classify:

1. `h` not finite: `DIANA_ERR_ARG`.
2. Every input element in index order, per index `y[j]` then `f[j]` (Euler), `y[j]` then `k[j]`
   (stage), `y[j]`, `k1[j]`, ..., `k4[j]` (step), or the sample `y[j]` (quadrature): the first
   non-finite one is `DIANA_ERR_ARG`.
3. Otherwise `DIANA_ERR_OVERFLOW`.

- Whole arrays are scanned, not only the failing component, so the status does not depend on
  which component failed first. Both errors leave the output untouched (KERNEL-002).
- A successful call never runs the classification: it does the check pass and the write as
  before, with no extra test.
- WP proves `DIANA_ERR_OVERFLOW` only with `h` and every input element finite (EULER-C1, RK4-C1,
  RK4-C2, TRAPEZOIDAL-C1, SIMPSON-C1). VST proves the exact status `euler_status`
  (`VST/Euler.v`), `stage_status`, `rk4_status` (`VST/RK4.v`), `trap_status`
  (`VST/Trapezoidal.v`) and `simpson_status` (`VST/Simpson.v`): 0 when every computed value is
  finite, else -5 when `h` and every input element are finite, else -1 (EULER-C2, RK4-C3,
  RK4-C4, TRAPEZOIDAL-C2, SIMPSON-C2).
- Newton, the substitution kernels, LU and the LU solve need no such pass: they test their
  inputs before computing, so a later non-finite value is an overflow (API-010, API-030, API-032,
  API-034). `diana_cholesky` reports an overflow as a pivot that is not positive (API-028), and
  the `_unchecked` kernels never return `DIANA_ERR_OVERFLOW` (API-018).
