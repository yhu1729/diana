`diana_norm_1`, `diana_norm_2` and `diana_norm_inf` take `(x, n, result)`, read `x[0 .. n-1]` once
in index order (the 2-norm twice) and write `*result` only on `DIANA_OK`.

1. `x` or `result` NULL: `DIANA_ERR_ARG`, nothing read. `n == 0` is valid: the loops do not run
   and the result is `+0`.
2. For `i = 0, ..., n-1`: `x[i]` not finite returns `DIANA_ERR_ARG` at once; otherwise
   `a = diana_fp_abs(x[i])` and the 1-norm sets `s = s + a` (from `s = 0.0`), the maximum norm
   `m = a` if `a > m` (from `m = 0.0`), the 2-norm the same and also `k = i`.
3. 1-norm: `s` not finite is `DIANA_ERR_OVERFLOW`, else `*result = s`. Maximum norm:
   `*result = m`; it has no overflow exit.
4. 2-norm: `m == 0.0` writes `0.0`. Otherwise `s = 1.0`, then for `i != k` in index order
   `q = x[i] / m` and `s = s + q * q`; `r = m * diana_fp_sqrt(s)`; `r` not finite is
   `DIANA_ERR_OVERFLOW`, else `*result = r`.

- A non-finite entry is found even after the 1-norm's sum has overflowed, so the status does not
  depend on where the overflow happens (API-036).
- Every result is `+0` or positive: `|-0|` is `-0`, `+0 + -0` is `+0` and `-0 > +0` is false.
- `k` is the first index of the largest magnitude; its term is the leading `1` of `s`, so the
  sum adds the other squares to 1 in index order (TEST-044 pins it).
- Each operation is rounded separately (`-ffp-contract=off`); the division by `m` is a correctly
  rounded division per entry, not a multiplication by `1/m`, which overflows for a subnormal `m`.
