`diana_axpy(a, x, n, y)` computes `y[i] = y[i] + a * x[i]` for `i = 0, ..., n-1` in place, the
product rounded before the sum (`-ffp-contract=off`, no FMA), and writes nothing unless `a` and
every component are finite.

1. `x` or `y` NULL: `DIANA_ERR_ARG`, nothing read or written.
2. `a` not finite (`diana_fp_finite`): `DIANA_ERR_ARG`, also for `n == 0`, so `DIANA_OK`
   always means a finite `a`. `n == 0` is otherwise valid: the loops do not run.
3. First pass: for each `i`, compute `r = y[i] + a * x[i]` and test it. At the first NaN or ±∞
   it tests `x[j]`, then `y[j]`, for `j = 0, ..., n-1`: the first non-finite one returns
   `DIANA_ERR_ARG`, none `DIANA_ERR_OVERFLOW`; `y` is untouched on both (API-036).
4. Second pass: recompute each component, bit for bit the same, store it over `y[i]`;
   `DIANA_OK`.

- The operand order `y[i] + a * x[i]` is the Euler step's `y[i] + h * f[i]` (API-015), so the
  binary64 model is the Euler one with `a` for `h` and `x` for `f` (PROOF-014); the IEEE sum is
  commutative, so `a * x[i] + y[i]` would give the same bits.
- Each `y[i]` is read before it is written, and `x` must not overlap `y` (API-004), so the
  second pass reads what the first read and the two passes agree.
- `a = ±0` still adds the signed zero `a * x[i]`: `-0 + +0` is `+0`, so `a = +0` turns a `-0`
  entry with a positive `x[i]` into `+0` (TEST-046); a NaN or infinite `x[i]` is
  `DIANA_ERR_ARG` whatever `a` is.
- The out-of-place form of the same update is `diana_euler_step(y, x, n, a, y_out)`.
