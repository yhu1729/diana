`diana.axpy(a, x, y)` updates `y` in place to `y[i] + a*x[i]` and returns `None`; it is the one
public function of the package that takes an output argument. `x` is an array argument
(API-020) of any length; a non-buffer iterable is copied into `array.array("d")` by `_samples`
in `python/src/diana/_axpy.py`. `y` is passed through to the extension as it is.

- The extension function `diana._diana.axpy` (keywords `a`, `x`, `y`; `a` converted by the `d`
  format, so a string is `TypeError`) reads `x` with `diana_py_get_array` (minimum length 0,
  `PyBUF_RECORDS_RO`) and `y` writable (`PyBUF_RECORDS`): a list or tuple is `TypeError` from
  `PyObject_GetBuffer`, a read-only buffer raises its own error (`BufferError` for `bytes` and a
  read-only memoryview, `ValueError` for a NumPy array with `writeable = False`).
- Then `ValueError` when the lengths differ (`y must have the same length as x`) or the byte
  ranges overlap (`y must not overlap x`, `diana_py_overlap`); two slices of one NumPy array
  may be used when they do not overlap.
- An empty `x` and `y` may expose dummy pointers (API-038), so the call passes the addresses of
  two local doubles for `n == 0`; the kernel still tests `a`.
- `DIANA_ERR_ARG` raises `ValueError` (`axpy input is not finite: a, x or y`),
  `DIANA_ERR_OVERFLOW` `diana.FloatOverflowError` (`axpy result overflows`, API-022); the kernel
  leaves `y` untouched on both.
- The GIL is held during the call, as for every array function.
