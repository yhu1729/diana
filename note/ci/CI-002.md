---
id: CI-002
title: Path filters; extend the matching .change_* list when a job reads a new file
kind: rule
path:
  - .gitlab-ci.yml
related: [CI-001, CI-014]
---
A filtered job runs only when a file on its `.change_*` list changes, so when you add a job, or a
file an existing job reads, extend the matching list at the top of `.gitlab-ci.yml`; otherwise
the job silently skips the change. Each filtered job has `rules: [*rule_full, changes: *list]`:

- `.change_c`: `build_*`, `test_<cc>_<config>`, `test_install`, `coverage_c`
- `.change_python`: `test_python`, `coverage_python`
- `.change_style`: `style_python`; `.change_style_c`: `style_c`; `.change_any`: `style_name`
- `.change_frama_c`: `verify_frama_c`; `.change_lean`: `verify_lean`; `.change_rocq`: `verify_rocq`

Every list contains `.gitlab-ci.yml`, so a change to it runs every job. `.rule_full`
(`$CI_COMMIT_TAG || $CI_PIPELINE_SOURCE == "schedule"`) runs every filtered job in tag and
scheduled pipelines, so a release is gated on a full run. `coverage_c` and `coverage_python` also
run on every default-branch pipeline (`$CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH`), even for a push
that changes only Markdown, so the README coverage badges (`job=coverage_c`,
`job=coverage_python` on `main`) always have a value; `CI_COMMIT_BRANCH` is unset in a
merge-request pipeline, which keeps the path filters. `style_git` has no `rules:` and runs in
every pipeline; `release` runs only for a version tag.

Because a filtered job can be absent, a `needs:` on a job of another list is `optional: true`.
Gaps in the current lists: `.change_frama_c` lacks `script/job_count.sh`, which
`script/verify_frama_c.sh` calls; `.change_style_c` and `.change_any` list `.clang-tidy` and
`.editorconfig`, which no CI job reads; `.change_any` has no `doc/`, `note/` or `.git-hooks/`.
