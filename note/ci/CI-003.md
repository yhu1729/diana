id: CI-003
title: CI runs only Linux x86-64 containers; macOS branches are checked only locally
kind: fact
path:
  - .gitlab-ci.yml
  - CMakeLists.txt
  - script/check_wheel.py
related: [VERIFY-001, VST-001, FP-005, COMPILER-001]
---
Every job runs in a public Linux container image and none sets `tags:`, so on GitLab.com the jobs
run on the shared x86-64 Linux runners. Images: `ghcr.io/astral-sh/uv:python3.13-bookworm-slim`
(template `.uv`: `style_c`, `style_python`, `test_python`, both coverage jobs), `gcc:14` and
`silkeh/clang:18` (builds, ctest, `test_install`), `alpine:3.20` (`style_name`, `style_git`),
`framac/frama-c:32.1`, `debian:bookworm-slim` (`LEAN_IMAGE`),
`mathcomp/mathcomp:2.6.0-rocq-prover-9.2`, and
`registry.gitlab.com/gitlab-org/release-cli:v0.24.0`.

CI therefore never takes the macOS branches:

- `APPLE` in `CMakeLists.txt`: with scikit-build and `DIANA_BUILD_SHARED_LIB=ON`, the `@rpath`
  install name of `libdiana` and the `@loader_path` RPATH of `_diana` (CI exercises the Linux
  `$ORIGIN` branch through `script/check_wheel.py` in `test_python`);
- the forwarding of `CMAKE_OSX_ARCHITECTURES`, `CMAKE_OSX_SYSROOT` and
  `CMAKE_OSX_DEPLOYMENT_TARGET` to the `find_package` consumer test;
- the `libdiana.dylib` case of `script/check_wheel.py`.

There is no Windows branch anywhere. The checks that run only locally (VERIFY-001) are tied to
AArch64 macOS: every committed Clight AST is `verification/clight/*_aarch64_macos.v` (VST-001).
So the x86-64 Linux binaries CI builds and tests are not the target the VST proofs and the
compiler comparison (COMPILER-001) cover (FP-005).
