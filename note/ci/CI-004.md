`style_c` runs `clang-format --dry-run --Werror` on every `*.c` and `*.h` under `include/`,
`src/`, `test/c/`, `test/install/`, `python/ext/` and `benchmark/` (`find ... -name '*.[ch]'`),
the same file set as `script/dev.sh test`; any reformatting fails the job.

- It extends `.uv` but replaces the template's `before_script` with `uv --version`, so it skips
  the apt install of `build-essential`, `cmake` and `ninja-build`.
- It installs only the `lint` group (`uv sync --only-group lint`), which builds nothing, and runs
  `clang-format` with `uv run --no-sync`: the version pinned there (`clang-format==23.1.3`) is
  the one local runs use. It prints `clang-format --version` first.
- The C examples in `doc/api/` are checked by `test_python` through `test/doc/` (TEST-003).
  The benchmark sources are formatted here but never built or run in CI (BENCHMARK-003).
- The four `build_*` jobs need it (optionally), so a format failure stops the C build, test and
  release chain in that pipeline.

Path list `.change_style_c` (CI-002).
