---
id: CI-006
title: style_name rejects six fixed plural directory names, two levels deep
kind: fact
path:
  - .gitlab-ci.yml
related: [STYLE-001, CI-002]
---
`style_name` rejects only directories named `tests`, `docs`, `scripts`, `proofs`, `wrappers` or
`tools`, found by `find . -maxdepth 2 -type d` (top-level directories and their direct children)
outside `./.git/`, `./.venv/` and `./build/`; it prints `plural directory name not allowed` with
the paths and fails. It is not a general plural check: any other plural name (the tracked
`.git-hooks/`, for one) and those six names three or more levels deep pass.

It runs on `alpine:3.20` with path list `.change_any` (CI-002), which has no `doc/`, `note/`,
`.git-hooks/` or top-level Markdown entry. Because it scans the tree whenever it runs, a bad
directory added in a push that skipped it is caught by the next pipeline that runs it; every tag
and scheduled pipeline does. The naming rule it partly enforces is STYLE-001.
