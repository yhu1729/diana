Four jobs build the C library and the ctest suite, one per compiler and configuration:
`build_gcc_debug`, `build_gcc_release`, `build_clang_debug`, `build_clang_release`. Each extends
three templates:

- `.gcc` (image `gcc:14`, `CC=gcc`) or `.clang` (`silkeh/clang:18`, `CC=clang`), whose
  `before_script` apt-installs `cmake` and `ninja-build`;
- `.debug_config` (`BUILD_TYPE=Debug`, `SANITIZER=ON`, so ASan and UBSan) or `.release_config`
  (`Release`, `OFF`);
- `.build`: `cmake -S . -B build -G Ninja` with `CMAKE_BUILD_TYPE=$BUILD_TYPE`,
  `DIANA_BUILD_TEST=ON`, `DIANA_SANITIZER=$SANITIZER`, `DIANA_WERROR=ON`,
  `DIANA_BUILD_PYTHON=OFF` and `CMAKE_C_COMPILER=$CC`, then `cmake --build build`.

So CI builds C only (no Python headers needed), with warnings as errors and the default static
library. The whole `build/` directory is the artifact (kept 1 day) that the `test_*` job of the
same name runs ctest on (CI-009). Rules: `.rule_full` or `.change_c`; `needs: style_c`
(optional). The extension is built by the `.uv` jobs instead (`style_python`, `test_python`,
`coverage_python`), the shared library by `test_install`, and the coverage build by `coverage_c`
(CI-010). BUILD-002 lists the CMake options.
