- `test_gcc_debug`, `test_gcc_release`, `test_clang_debug`, `test_clang_release` each need the
  build job of the same name and run `ctest --test-dir build --output-on-failure` on its `build/`
  artifact. The build has `DIANA_BUILD_TEST=ON` outside scikit-build, so ctest also runs the
  `install` and `find_package` tests (install into the build tree, then build and run the
  `test/install/` consumer). On failure `build/Testing` is kept a week.
- `test_install` (`gcc:14`, after `build_gcc_release`) configures, builds and runs ctest twice
  from scratch, Release with `DIANA_WERROR=ON` and `DIANA_BUILD_PYTHON=OFF`: `build/install-custom`
  with `CMAKE_INSTALL_INCLUDEDIR=include/custom` and `build/install-shared` with
  `DIANA_BUILD_SHARED_LIB=ON`, so the exported include path and the versioned shared install are
  covered.
- `test_python` (`.uv`, `needs: []`) runs `uv sync --group test --group lint`, `uv run pytest -q`
  (testpaths `test/python` and `test/doc`, so it includes the `doc/api/` example check, TEST-003,
  with the pinned clang-format from `lint`), `uv build` (sdist and wheel in `dist/`, kept a week),
  `twine check dist/*`, and `script/check_wheel.py`. That script builds a static and a shared
  wheel with `DIANA_WERROR=ON` and `DIANA_SANITIZER=OFF`, checks which `libdiana` runtime each
  packages and that no header, `.a` or `.cmake` file is in it, installs each into a fresh venv,
  and runs an import and bisection smoke test.

`.change_python` lists `doc/api/`, `.clang-format`, `README.md` and `LICENSE` because the example
check and the package metadata read them (the `readme` and `license-files` of `pyproject.toml`).
