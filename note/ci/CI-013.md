title: verify_rocq compiles layer A only, with Coquelicot on the MathComp image
kind: fact
path:
  - .gitlab-ci.yml
  - verification/rocq/Makefile
related: [PROVER-007, VERIFY-001, CI-002]
---
`verify_rocq` (image `$ROCQ_IMAGE`, `mathcomp/mathcomp:2.6.0-rocq-prover-9.2`, `needs: []`,
timeout 1 h) runs `rocq --version`, `opam update -y rocq-released`, `opam install -y
coq-coquelicot.$COQUELICOT_VERSION` (3.4.5), then `make real` in `verification/rocq`. Coquelicot
lets layer A use real integrals and derivatives; the repository index is updated first so that
version is available.

`make real` compiles, in order, the ten `theory/Real/*.v` files listed by hand in
`verification/rocq/Makefile` (PROVER-007); a new layer-A file that is not added there is never
compiled in CI. The job does not run `make check`, which compiles the generated `CheckSpec.v`
importing every layer, so it has no Rocq axiom gate.

No CI image carries Flocq, CompCert or VST, so every CI image is a public stock one. Layers B and
C-VST, the Rocq axiom gate and the Clight AST are checked only locally (VERIFY-001). Path list
`.change_rocq`: `.gitlab-ci.yml` and `verification/rocq/**`, so a change to the Float or VST
theories also runs the job although it compiles only `theory/Real/`.
