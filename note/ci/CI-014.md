title: release runs on a version tag once every test and verify job passes
kind: fact
path:

---
`release` runs only in a pipeline for a tag matching `^v\d+\.\d+\.\d+`, on the unpinned image
`registry.gitlab.com/gitlab-org/release-cli:latest`; its `release:` keyword creates the GitLab
release for `$CI_COMMIT_TAG` with the description `See CHANGELOG.md`.

Its `needs:` (none optional) are `test_gcc_release`, `test_gcc_debug`, `test_clang_release`,
`test_clang_debug`, `test_python`, `test_install`, `verify_frama_c`, `verify_lean` and
`verify_rocq`; `.rule_full` makes every one of them run in a tag pipeline (CI-002). `style_c` gates
it indirectly, since the builds need it and the tests need the builds.

`style_git`, `style_name`, `style_python`, `coverage_c` and `coverage_python` are not in that
chain: with `needs:`, `release` starts once its needs succeed, even if one of those failed; the
pipeline is then still marked failed. Pushing a tag needs an explicit request (GIT-008).
