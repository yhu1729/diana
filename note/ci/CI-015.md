`ci/docker/lean.Dockerfile` adds the pinned Lean toolchain and the Mathlib cache to
`debian:bookworm-slim`, so `verify_lean` does not fetch Mathlib on every run. No CI job builds or
pushes it, and `LEAN_IMAGE` in `.gitlab-ci.yml` still names the stock `debian:bookworm-slim`.

Contents: apt `curl git ca-certificates zstd python3 python3-yaml` (`python3-yaml` for
`script/check_spec.py`); elan in `/root/.elan`, with `/root/.elan/bin` on `PATH`, and the
toolchain of `lean-toolchain`; in `/opt/diana-lean` (exported as `DIANA_LEAN_CACHE`) copies of
`lean-toolchain`, `lakefile.toml` and `lake-manifest.json`, and the `.lake/packages` that
`lake exe cache get` leaves there, run against a stub `Diana.lean` that imports Mathlib and is
removed afterwards. There is no `USER` line: it runs as root like the stock images, so the job's
apt step still works on it.

1. From the repository root (the `COPY` sources are repository paths), run
   `docker build -f ci/docker/lean.Dockerfile -t <registry>/<image>:<tag> .`.
2. Push the image to a registry the GitLab runners can pull from.
3. Set `LEAN_IMAGE` to it in `.gitlab-ci.yml`, or as a project CI/CD variable, which overrides
   the file's value. `verify_lean` then skips the elan install and copies the packages (CI-012).
4. Rebuild and push again whenever `verification/lean/lean-toolchain`, `lakefile.toml` or
   `lake-manifest.json` changes, so the image's toolchain and packages match the checkout.
