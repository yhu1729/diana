`verify_provenance` (stage `verify`, `needs: []`, `alpine:3.20` with `git` and `python3` from
`apk`) runs `python3 script/check_provenance.py`, which needs only the Python standard library, git
and the checkout: no CompCert and no prover. It fails when:

- a committed Clight AST, its source or a header it includes differs from
  `verification/clight/manifest.txt`, or the manifest and the ASTs disagree (VST-009);
- `doc/verification/report.md` has no stamp, or a digest of one of its inputs (`include/`,
  `script/axiom_allow.yaml`, `script/run_frama_c.sh`, `spec/`, `src/`, `verification/`) differs
  from the checkout (GATE-009);
- the report has no theorem row, a Lean or Rocq cell other than `ok` or `–`, or a Frama-C cell
  other than `ok (N/N)` or `–`.

So a change to one of those inputs fails CI until a local `script/dev.sh verify` has rewritten
the manifest and the report and both are committed, which VERIFY-001 asks for. It establishes
freshness, not proof: the hashes are written on the developer's machine, a hand edit can forge
them, and layers B and C-VST are still checked only locally. Like `verify_lean` it uses the image's
system `python3`, not uv (CI-012). `git config --global --add safe.directory "$CI_PROJECT_DIR"`
lets git read the runner's checkout, as in `style_git` (CI-005). Path list `.change_provenance`:
`.gitlab-ci.yml`, `.gitignore`, the stamp's inputs, `doc/verification/report.md` and
`script/check_provenance.py`; `release` needs the job (CI-014).
