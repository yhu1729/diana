---
id: CI-017
title: GitHub Actions mirror the GitLab jobs, one workflow per path list
kind: fact
path:
  - .github/workflows/*.yml
related: [CI-001, CI-014, CI-018, CI-019, CI-023]
---
GitLab CI is the primary pipeline. The GitHub repository is a push mirror of the GitLab project,
so every push to GitLab reaches GitHub and runs `.github/workflows/`, a second pipeline over the
same commits. Each workflow holds the jobs of one GitLab path list (CI-018), under the GitLab
job names:

- `style_git`, `style_name`, `style_c`, `style_python`: the GitLab job of the same name;
- `c`: `test_{gcc,clang}_{debug,release}` (each a GitLab `build_*` and `test_*` pair),
  `test_install`, `coverage_c`, and the macOS `test_macos_{debug,release}` and
  `test_install_macos` (CI-023);
- `python`: `test_python_{3.12,3.13,3.14}` (CI-024), `test_python_macos`, `coverage_python`;
- `verify_frama_c`, `verify_lean`, `verify_rocq`: the GitLab job of the same name.

Triggers: a push to any branch, a push of a tag matching `v[0-9]+.[0-9]+.[0-9]+` (GitHub's filter
syntax, matched against the whole name, so `v1.0.0-rc1` does not match), and `workflow_dispatch`,
a manual run. Unlike GitLab, a branch push without a merge request runs CI, because a mirrored
branch has no merge request on GitHub. Every workflow but `style_git` (CI-019) has the
concurrency group `<workflow>-<ref>` with `cancel-in-progress`, so a newer push cancels the
superseded run, as `interruptible` and GitLab's auto-cancel do (CI-001).

Every workflow has `permissions: contents: read`, uses no secret and has no release, publishing
or deployment job; `release` stays GitLab's (CI-014). Timeouts: `verify_lean` 120 min, every
other job 60 min, GitLab's default project timeout. There is no retry on runner failure, and no
job waits for a job of another workflow, so the builds do not wait for `style_c`.
