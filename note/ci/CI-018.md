---
id: CI-018
title: Keep each GitHub workflow's paths equal to its GitLab .change_* list
kind: rule
path:
  - .github/workflows/*.yml
  - .gitlab-ci.yml
related: [CI-002, CI-017]
---
Every workflow but `style_git` filters `on.push.paths` by the GitLab path list of its jobs, so a
change to a `.change_*` list (CI-002) changes the `paths:` of its workflow in the same commit:

- `.change_c`: `c.yml`; `.change_python`: `python.yml`; `.change_style`: `style_python.yml`;
  `.change_style_c`: `style_c.yml`; `.change_any`: `style_name.yml`;
- `.change_frama_c`, `.change_lean`, `.change_rocq`: `verify_frama_c.yml`, `verify_lean.yml`,
  `verify_rocq.yml`.

The translation: `.gitlab-ci.yml` becomes the workflow file itself, and `dir/**/*` becomes
`dir/**`. `style_python.yml` lists all of `.github/workflows/**`, and `.change_style` lists
`.github/workflows/**/*`, because `script/check_doc.py` fails when a note's `path` names a
workflow file that no longer exists.

GitHub evaluates the filters differently in places:

- a tag push ignores path filters, so a version tag runs every workflow, as `.rule_full` does;
  so does `workflow_dispatch`;
- a push to an existing branch is compared with the branch's previous head, a new branch with
  the parent of the oldest commit it pushes; a push of more than 1,000 commits always runs, and
  one whose diff has over 3,000 files with no match among the first 3,000 does not;
- no workflow has a `schedule:` trigger, and `coverage_c` and `coverage_python` do not also run
  on every default-branch push, since nothing on GitHub reads a coverage badge.
