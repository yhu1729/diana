---
id: CI-018
title: The change job selects the GitHub jobs from the GitLab .change_* lists
kind: fact
path:
  - script/ci_change.py
  - test/python/test_ci_change.py
  - .github/workflows/ci.yml
  - .gitlab-ci.yml
related: [CI-002, CI-017]
---
The first job of `ci.yml`, `change`, clones the full history and runs `script/ci_change.py`, which
reads every `.change_<list>` anchor of `.gitlab-ci.yml` (CI-002) and writes `<list>=true|false`
to `$GITHUB_OUTPUT`; each job then runs when its list is true, as its GitLab job does under
`rules: changes`. The two pipelines read one path list, so there is nothing to keep in sync.

- Every list is true for a tag push and a `workflow_dispatch`, as `.rule_full` makes every GitLab
  job run, and when a changed file is `.gitlab-ci.yml`, `ci.yml`, `c_test.yml` or the script.
- A push to the default branch compares `github.event.before` with `github.sha` through their
  merge base: the files of that push, since no run there is cancelled (CI-017). A first push
  (`before` all zeros) or an old head the clone lacks (a force push) makes every list true.
- A push to any other branch compares `github.sha` with its merge base with
  `origin/<default branch>`, the range `style_git` checks (CI-019): every file the branch changes,
  whatever the previous push was. `cancel-in-progress` cancels the run a newer push supersedes, so
  a run must cover the cancelled run's changes too, which a diff from the previous push would
  not: a `src/` push followed by a documentation push would leave the branch head green with the
  C, WP and proof jobs never run. A branch at the default branch's tip has no changed file, and
  no list is true. Without the default branch in the clone, every list is true.
- Patterns follow GitLab's `File.fnmatch` with `FNM_PATHNAME | FNM_DOTMATCH`: `*` and `?` stop at
  `/`, `**/` spans directories, and a leading dot needs no explicit match.
- A branch deletion (`github.event.deleted`) skips `change`, and with it every job.

No job has a `schedule:` trigger, and `coverage_c` and `coverage_python` do not also run on every
default-branch push, since nothing on GitHub reads a coverage badge. `test/python/test_ci_change.py`
checks the parsing against the real `.gitlab-ci.yml`, the glob rules and the base selection; the
base-selection test runs `git` and is skipped without it, as in the uv images of `test_python`
(CI-020), so `test_python_macos` and local runs cover it.
