---
id: CI-019
title: GitHub style_git passes the push range to check_commit.sh as GitLab variables
kind: fact
path:
  - .github/workflows/style_git.yml
  - script/check_commit.sh
related: [CI-005, GIT-007, CI-017]
---
`style_git.yml` runs `script/check_commit.sh` unchanged on the `ubuntu-24.04` runner after a full
clone (`fetch-depth: 0`), with `CI_COMMIT_SHA` set to `github.sha` and `CI_COMMIT_BEFORE_SHA` to
`github.event.before`; the runner sets `CI=true`. The script then picks the range as in GitLab
(CI-005):

- a push to an existing branch: `before..sha`, the commits the push added; when the mirror
  carries several GitLab pushes in one, the commits of all of them;
- a new branch or tag (`before` all zeros), a force push (the old head is in no fetched ref, so
  not in the clone) and `workflow_dispatch` (`before` empty): the whole history of `sha`.

The workflow has no path filter and no concurrency group: cancelling a superseded run would leave
the commits of its push unchecked, because the next run starts from the newer `before`. The job
skips a branch deletion (`github.event.deleted`), whose ref no longer exists to check out. Its
`awk` is Ubuntu's default `mawk`, where GitLab's `alpine:3.20` has the BusyBox `awk`.
