---
id: CI-019
title: GitHub style_git checks a range no cancelled run can skip
kind: fact
path:
  - .github/workflows/ci.yml
  - script/check_commit.sh
related: [CI-005, GIT-007, CI-017]
---
The `style_git` job of `ci.yml` runs `script/check_commit.sh` unchanged on the `ubuntu-24.04`
runner after a full clone (`fetch-depth: 0`), with `CI_COMMIT_SHA` set to `github.sha`; the runner
sets `CI=true`. It needs no other job, has no path filter, and sets the GitLab variable that gives
the GitLab range of the same kind of pipeline (CI-005):

- a push to the default branch: `CI_COMMIT_BEFORE_SHA` is `github.event.before`, so `before..sha`,
  the commits of the push, as in a GitLab default-branch pipeline;
- a push to any other branch, new or forced included: `CI_MERGE_REQUEST_DIFF_BASE_SHA` is the
  merge base with the default branch, so every commit of the branch, as in a merge-request
  pipeline, since a mirrored branch has no merge request;
- a tag push and `workflow_dispatch` set neither: the whole history of `sha`, as a GitLab tag or
  scheduled pipeline.

`ci.yml` cancels a superseded run (CI-017), and a cancelled `style_git` checks nothing, so the range
is chosen so that the next run covers it: on a branch every run checks the whole branch, and on the
default branch, where each run checks only its push, the concurrency group carries the commit, so
no run there is ever cancelled. The job skips a branch deletion (`github.event.deleted`), whose ref
no longer exists to check out. Its `awk` is Ubuntu's default `mawk`, where GitLab's `alpine:3.20`
has the BusyBox `awk`.
