The Linux jobs run on the `ubuntu-24.04` runner inside the image of their GitLab job
(`container:`), named by the same tag plus its digest (`gcc:14@sha256:…`, CI-025), and run the
GitLab script lines unchanged, the shell variables of the `cmake` lines quoted:

- `test_<cc>_<config>` configure, build and run ctest in one job, a call of the reusable
  `c_test.yml` with the compiler, configuration and image, so no `build/` artifact passes between
  jobs; `build/Testing` is kept 7 days when a step fails;
- `test_install`, `coverage_c`, `style_c`, `style_python` and `coverage_python` run as in GitLab;
- `test_python_<version>` runs once per Python version (CI-024) and keeps its `dist/` 7 days.

`style_name` and `style_git` run on the runner itself instead of `alpine:3.20`. In an image
without `git` (the uv images), `actions/checkout` downloads the tree through the REST API and
leaves no `.git`; no step there runs `git`. The coverage reports, HTML and Cobertura, are the
artifacts `coverage-c` and `coverage-python`, kept 30 days; GitHub reads no coverage value from
the log, so there is no badge.
