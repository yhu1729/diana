id: CI-021
title: GitHub runs the Frama-C and Rocq images with docker run, as their own users
kind: fact
path:
  - .github/workflows/verify_frama_c.yml
  - .github/workflows/verify_rocq.yml
related: [CI-011, CI-013, CI-025]
---
`framac/frama-c:32.1` runs as the user `opam` and `mathcomp/mathcomp:2.6.0-rocq-prover-9.2` as
`rocq`, and both have the entrypoint `opam exec --`, which puts the opam switch on `PATH`. A
GitHub `container:` job replaces the entrypoint and runs its steps as the image user in a checkout
the runner owns, so the provers would not be on `PATH` and could write nothing. The two workflows
therefore check out on the runner, run `chmod -R a+rwX .` (what the default umask `0000` of
GitLab's Docker executor achieves), and run the GitLab script lines in one
`docker run --rm -v "$PWD:/work" -w /work <image> sh -c '…'`, which keeps the entrypoint and user:

- `verify_frama_c`: `frama-c -version && script/verify_frama_c.sh`; `DIANA_JOB` is unset, so the
  runner's CPU count (`nproc` in the container) sets the rows at a time; `report.txt` is the
  artifact `frama-c-report`, kept 30 days, also when the job fails;
- `verify_rocq`: `rocq --version`, `opam update -y rocq-released`,
  `opam install -y coq-coquelicot.$COQUELICOT_VERSION` (3.4.5) and `make real` in
  `verification/rocq`, within 60 min.

Both images exist for `linux/amd64` only.
