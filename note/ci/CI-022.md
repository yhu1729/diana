id: CI-022
title: GitHub verify_lean installs elan on stock Debian and caches with actions/cache
kind: fact
path:
  - .github/workflows/verify_lean.yml
  - verification/lean/lean-toolchain
  - verification/lean/lake-manifest.json
related: [CI-012, CI-015]
---
`verify_lean` runs in `debian:bookworm-slim` (digest-pinned) and follows the stock-image branch of
the GitLab `before_script` (CI-012): apt `curl git ca-certificates zstd python3 python3-yaml`
before the checkout, so the checkout is a git clone; then elan from `elan-init.sh` on elan's
`master`, with the toolchain of `lean-toolchain`, into `$GITHUB_WORKSPACE/.cache/elan`, whose
`bin` goes on `PATH` through `$GITHUB_PATH`. It has no `DIANA_LEAN_CACHE` branch, since no
project image is in a registry (CI-015). Then `lake exe cache get && lake build` and
`python3 script/check_spec.py --run --strict --prover lean --no-report` under Debian's Python
3.11, within 120 min.

`actions/cache` keeps `.cache/elan` and `verification/lean/.lake/build`, the paths of the GitLab
job cache, under the key `lean-<hash of lean-toolchain and lake-manifest.json>-<commit>`, and
restores the newest entry with the same hash prefix. A GitHub cache entry cannot be overwritten,
hence the commit in the key, and a branch reads only its own entries and the default branch's.
Mathlib's packages are not cached, so `lake exe cache get` downloads them on every run, as in
GitLab.
