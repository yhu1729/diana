title: GitHub verify_lean installs elan on stock Debian and caches Lean and Mathlib
kind: fact
path:
  - .github/workflows/ci.yml
  - verification/lean/lean-toolchain
  - verification/lean/lake-manifest.json
related: [CI-012, CI-015, CI-026]
---
`verify_lean` runs in `debian:bookworm-slim` (digest-pinned) and follows the stock-image branch of
the GitLab `before_script` (CI-012): apt `curl git ca-certificates zstd python3 python3-yaml` before
the checkout, so the checkout is a git clone; then, unless the cache restored it, elan from
`elan-init.sh` on elan's `master`, with the toolchain of `lean-toolchain`, into
`$GITHUB_WORKSPACE/.cache/elan`, whose `bin` goes on `PATH` through `$GITHUB_PATH`. It has no
`DIANA_LEAN_CACHE` branch, since no project image is in a registry (CI-015). Then `lake exe cache
get && lake build` and `python3 script/check_spec.py --run --strict --prover lean --no-report` under
Debian's Python 3.11, within 120 min.

Three `actions/cache` entries keep `.cache/elan`, `verification/lean/.lake/packages` and
`verification/lean/.lake/build` under keys of their inputs (CI-026). With the packages restored,
`lake exe cache get` finds Mathlib's compiled files present and downloads nothing, where the GitLab
job, which caches only `.cache/elan` and `.lake/build`, downloads them on every run.
