Four jobs run on the `macos-15` runner (AArch64, the Apple clang of its Xcode, and the runner
image's CMake and Ninja), the platform GitLab never tests (CI-003):

- `test_macos_debug` and `test_macos_release`: the commands of `test_<cc>_<config>` with
  `CC=clang`, ASan and UBSan in Debug; ctest's `find_package` test takes the branch that
  forwards `CMAKE_OSX_ARCHITECTURES`, `CMAKE_OSX_SYSROOT` and `CMAKE_OSX_DEPLOYMENT_TARGET`, with
  the empty values a plain configure gives them;
- `test_install_macos`: the commands of `test_install`, so the shared build exports through
  `-exported_symbols_list` and the ctest `symbol` checks the `.dylib`;
- `test_python_macos`: the commands of `test_python`, with uv from `astral-sh/setup-uv` and the
  Python of `.python-version`; `script/check_wheel.py` checks the shared wheel's `@rpath` install
  name, `@loader_path` RPATH and `libdiana.dylib`.

These binaries come from Apple clang, not from the CompCert build the VST proofs are about
(FP-005), although architecture and system match the committed ASTs (`*_aarch64_macos.v`).
