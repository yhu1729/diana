A verified kernel calls no `<math.h>` function (`fabs`, `isfinite`, `fma`, …) and no other
external function outside Diana; the `src/fp.h` helpers (FP-002) provide finiteness and absolute
value with plain IEEE arithmetic instead.

- Every external call would need an axiomatised specification in both VST and Frama-C, a trusted
  assumption the trust base does not have.
- CompCert's `clightgen` cannot parse the macOS `<math.h>`, so a kernel that includes it has no
  Clight AST on the target the ASTs are generated on (VST-001).
- Frama-C's own libc declares math functions such as `fabs` with an ACSL contract and no body,
  and `script/run_frama_c.sh` fails when WP would assume the contract of a called body-less
  function that is not in `SKIP` (WP-003), so such a call in a kernel stops the WP run.

Today no file under `src/` or `include/` includes `<math.h>`. The square root of `diana_cholesky` is
`__builtin_sqrt` in the helper `diana_fp_sqrt`, a compiler builtin rather than a libm call; its WP
contract and its VST funspec are assumed and documented (FP-006). The rule covers only the verified
kernels; the C tests (linked with `m` in `test/c/CMakeLists.txt`) and the Python extension
(`python/ext/newton_step.c` uses `isfinite`) may use libm.
