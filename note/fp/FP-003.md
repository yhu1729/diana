---
id: FP-003
title: src/fp.h asserts FLT_EVAL_METHOD == 0 at compile time
kind: fact
path:
  - src/fp.h
related: [FP-002, FP-004, FP-005]
---
`src/fp.h` includes `<float.h>` and declares
`_Static_assert(FLT_EVAL_METHOD == 0, "Diana requires binary64 evaluation of double expressions")`,
so every kernel source that includes it fails to compile on a compiler that evaluates `double`
expressions in a wider format.

- The models round every operation to binary64. An x87 build (`FLT_EVAL_METHOD == 2`) keeps
  intermediates in extended precision and double-rounds; the strict flags of FP-004 do not change
  the evaluation format, so the build checks it instead.
- x86-64 (SSE2) and AArch64 have `FLT_EVAL_METHOD == 0`.
- The assertion is a declaration and generates no code. It was added (commit `3131fe5`) without
  any change to the committed Clight ASTs or to the WP goal counts in
  `verification/frama-c/expectation.txt`.
- Only sources that include `src/fp.h` carry it: the checked kernels that test finiteness. The
  unchecked kernels, `src/bisection_mid.c`, `src/bisection_result.c`, `src/newton_result.c`, the
  callback wrappers, `src/status_str.c` and `src/version.c` do not include it.
