Diana is compiled with `-ffp-contract=off -fno-fast-math -fno-math-errno` (and
`-fexcess-precision=standard` on gcc) and never with a fast-math or contraction flag (FP-007):
the proofs assume each operation rounded separately to binary64, in source order.

- `-ffp-contract=off` forbids fusing `y[i] + h * f[i]` into one FMA, which rounds once instead of
  twice and so differs from the model. `-fno-fast-math` undoes a fast-math flag given earlier on
  the command line, keeping NaN, infinities, signed zeros and the evaluation order.
- `-fno-math-errno` lets gcc, and clang on Linux, compile the `__builtin_sqrt` of
  `diana_fp_sqrt` (`src/fp_sqrt.c`) to the square-root instruction alone; with `errno` semantics
  they add a call to the libm `sqrt` for a negative argument, which `diana_cholesky` never
  passes, and gcc at `-O0` calls it always. It changes no result.
- `diana_set_strict_flag` in `cmake/warning.cmake` adds these as `PRIVATE` options to `diana`,
  `_diana` and each `test_<name>`, so a consumer's own flags do not reach the library's code (no
  public header contains arithmetic). It adds them only for compiler IDs `GNU`, `Clang` and
  `AppleClang`; configuration refuses any other compiler unless `DIANA_ALLOW_UNKNOWN_COMPILER`
  is ON, and then builds without them (BUILD-013).
- Configuration stops when `CMAKE_C_FLAGS` or a per-configuration variant contains a fast-math,
  contraction or fast-model flag (FP-007).
- C11 without extensions (`CMAKE_C_STANDARD 11`, `CMAKE_C_EXTENSIONS OFF`, so `-std=c11`).
- Builds outside CMake pass the flags themselves: `script/compare_compiler.sh` all of them
  (`-fexcess-precision=standard` when the compiler is gcc), `test/doc/test_example.py`
  `-std=c11 -ffp-contract=off -fno-fast-math -fno-math-errno`.

None of this sets the runtime floating-point environment (rounding mode, flush-to-zero, traps),
which stays the caller's responsibility (API-001); `FLT_EVAL_METHOD` is checked in the source
(FP-003).
