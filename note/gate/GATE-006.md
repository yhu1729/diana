title: When and how the gate rewrites doc/verification/report.md
kind: fact
path:
  - script/check_spec.py
  - doc/verification/report.md
  - verification/frama-c/expectation.txt
related: [GATE-007, GATE-009, WP-007, VERIFY-002]
---
The gate rewrites `doc/verification/report.md` only on a `--run` with both provers selected (no
`--prover`, or `--prover lean --prover rocq` in that order) and without `--no-report`. A
structural run or a one-prover run leaves the committed report alone, since it would show the
prover that did not run as `planned`.

- Everything above `<!-- generated by script/check_spec.py; do not edit below -->` is kept and
  the rest regenerated: the stamp of input digests and tool versions (GATE-009), then the table;
  a missing marker makes the gate exit 1, and so does a failure to list the inputs with git.
- Columns: Spec, ID, Layer, Lean, Rocq, Frama-C, Statement (the `informal` text, `|` escaped).
- Lean and Rocq cells: `–` when the theorem names no constant for that prover, else its status
  (`ok`, `missing`, `check failed`, `axiom: ...`, or `planned` when the prover project is
  absent).
- Frama-C cell: `–` without `acsl`; `ok (N/N)` when `verification/frama-c/expectation.txt` has
  exactly one row with a positive count `N` for the `acsl` file; `planned` with no row or no
  file; `unreadable` for a duplicate or malformed row. The gate runs no WP: `N` is the committed
  count that `script/verify_frama_c.sh` checks against a fresh run.
- The report is rewritten by the spec gate of `script/dev.sh verify` and committed; no CI job
  rewrites it (`verify_lean` and `style_python` pass `--no-report`).
