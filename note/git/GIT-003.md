---
id: GIT-003
title: Never amend; recreate rewritten commits so author date equals commit date
kind: procedure
path:
  - script/check_commit.sh
related: [GIT-004, GIT-007]
---
Every commit's author date equals its commit date (`%at` and `%ct`, to the second);
`script/check_commit.sh` rejects any other. `git commit --amend` keeps the author date and sets a
new commit date, and `git rebase` or `git cherry-pick` replay commits with their old author date,
so their results fail. Never amend. A mistake in a published commit gets a new corrective commit.
To rework unpublished commits, including ones a rebase just replayed:

1. List the commits to recreate, oldest first: `git log --reverse --format='%H %s' <good>..HEAD`,
   where `<good>` is the last commit to keep.
2. `git reset --soft <good>`.
3. For each listed commit in order: `git read-tree <sha>` (the index becomes that commit's tree;
   the working tree is untouched), then `git commit -s -m '<subject>'`.
4. Check with `script/check_commit.sh`; with no argument it covers the commits not yet on the
   upstream branch.

Do not reuse a message with `git commit -C <sha>` or `-c <sha>`: they copy the original author
date as well. Never bypass the hooks with `--no-verify`.
