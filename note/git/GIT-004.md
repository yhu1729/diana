---
id: GIT-004
title: Linear history, rebase onto the target and never merge
kind: rule
path:
  - script/check_commit.sh
related: [GIT-003, GIT-007, CI-005]
---
History is linear: no merge commits. `script/check_commit.sh` rejects any commit with more than
one parent (`merge commit; rebase instead of merging`), in the `pre-push` hook and in CI
`style_git`.

To bring a branch up to date with `main`, or to combine branches, rebase onto the target. A
branch that already descends from the target only fast-forwards. A rebase gives every replayed
commit a new commit date while keeping its author date, so recreate the replayed commits fresh
afterwards (GIT-003) before pushing.

A merged-results pipeline tests a merge commit that GitLab creates; `style_git` checks the source
branch's own commits instead (CI-005).
