---
id: GIT-005
title: One logical step per commit; library, test and doc are separate commits
kind: rule
related: [GIT-001, STYLE-004]
---
A commit is one logical step, usually one file: a header, a kernel, a test, a doc page. Group
files only when they make no sense apart, such as a `.c` file and the `CMakeLists.txt` line that
builds it, or a change and the `CHANGELOG.md`, `CLAUDE.md` or note update it makes necessary
(STYLE-004). A change that touches the library, its test and its documentation is three commits.

Example from the history: `build: rename DIANA_JOBS to DIANA_JOB` changes `script/dev.sh` and
`script/job_count.sh` with their `CHANGELOG.md` and `CLAUDE.md` lines; the next commit,
`doc: rename DIANA_JOBS to DIANA_JOB`, updates the `doc/` pages.

No script checks size or wording beyond articles (GIT-001).
