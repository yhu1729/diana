---
id: GIT-006
title: Link the commit-msg and pre-push hooks once per clone
kind: procedure
path:
  - .git-hooks/commit-msg
  - .git-hooks/pre-push
related: [GIT-001, GIT-007]
---
The hooks are tracked in `.git-hooks/`, but Git never activates hooks from a clone. Link them into
`.git/hooks` once per clone, from the repository root:

1. `ln -s ../../.git-hooks/commit-msg .git/hooks/commit-msg`
2. `ln -s ../../.git-hooks/pre-push .git/hooks/pre-push`

The links are relative to `.git/hooks`, so they survive moving the checkout and follow updates of
the tracked hooks. `ln -s` refuses to replace an existing hook file; a clone with its own hook
has to call the tracked one from it. `git config core.hooksPath .git-hooks` would also work, but
it replaces `.git/hooks` wholesale and so disables every other local hook.

- `commit-msg` drops `#` comment lines and everything below the `# ---- >8 ----` scissors line,
  ignores trailing blank lines, and rejects an empty message or a subject not of the form of
  GIT-001. It checks nothing else.
- `pre-push` runs `script/check_commit.sh <local sha> --not --remotes=<remote>` for every pushed
  ref except deletions, so it checks the commits the remote does not have yet, and fails the push
  if any ref fails (GIT-007).

Never bypass them with `--no-verify`; fix the commit instead (GIT-003).
