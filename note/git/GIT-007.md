---
id: GIT-007
title: script/check_commit.sh checks and argument forms
kind: fact
path:
  - script/check_commit.sh
related: [GIT-001, GIT-002, GIT-003, GIT-004, CI-005]
---
`script/check_commit.sh [git log argument...]` checks every commit that
`git log --reverse <arguments>` lists, prints `<hash> <subject>: <reason>` for each failure and
`<n> commit(s) checked`, and exits 1 when any commit fails. Per commit it rejects:

- more than one parent, a merge commit (GIT-004);
- a subject not of the form `<type>[(scope)]: <summary>` with a listed type (GIT-001);
- a subject longer than 50 characters;
- `a`, `an` or `the` as a word of the summary;
- a non-blank second line, or anything after it other than one
  `Signed-off-by: <committer name> <committer email>` line (GIT-002);
- an author date different from the commit date (GIT-003).

Arguments are passed straight to `git log`: `HEAD` checks the whole history, `<a>..<b>` a range,
and the `pre-push` hook passes `<sha> --not --remotes=<remote>`. With no argument the script
chooses the range itself: outside CI (`CI` unset) `@{upstream}..HEAD`, or the whole history of
`HEAD` when the branch has no upstream; in CI from GitLab's variables (CI-005). A base that is not
a commit in the clone falls back to the whole history of the head. It changes to the repository
root first and needs only `sh`, `git` and `awk`.
