After a change to a VST-verified source or to a header it includes, regenerate its AST, on
AArch64 macOS only: an AST is never overwritten from another platform. CI `verify_provenance`
fails on an AST older than its source or headers (CI-016), but nothing in CI can regenerate it.

1. In the opam switch with CompCert, from the repository root:

   ```sh
   opam exec -- clightgen -normalize -Iinclude -Isrc \
       -o verification/clight/<source>_aarch64_macos.v src/<source>.c
   ```

   `DIANA_CLIGHT_UPDATE=1 script/dev.sh verify` does this for every committed AST of the current
   target and goes on to the proofs (VST-003).
2. `opam exec -- make -C verification/rocq` rechecks the VST proofs against the new AST; repair
   any proof that no longer compiles.
3. For a new source file, also add `../clight/<source>_aarch64_macos.v` and its
   `theory/VST/<Function>.v` to `verification/rocq/_CoqProject` (VST-004); the Clight check only
   regenerates ASTs that are already committed.
4. Run `script/dev.sh verify`, which records the AST in `verification/clight/manifest.txt`
   (VST-009) and rewrites the report, and commit the AST, the manifest and the report together
   with the source change that caused them.
