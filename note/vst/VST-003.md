title: dev.sh verify compares every committed AST of the current target

The first stage of `script/dev.sh verify` regenerates each committed AST of the current CompCert
target into a temporary directory and compares it byte for byte with the committed file.

- The target is read from `compcert.config` under `$(opam var lib)/coq/user-contrib/compcert/`
  or `$(opam var lib)/rocq/user-contrib/compcert/` of `DIANA_OPAM_SWITCH` (default: the current
  switch). If neither exists, `verify` stops with an error, so it needs CompCert in the switch
  even though the later compiler comparison would skip a missing `ccomp`.
- For each `verification/clight/*_<target>.v` it runs `clightgen -normalize -Iinclude -Isrc`
  on `src/<source>.c` and compares the result with `cmp`.
- A differing AST prints the first 40 lines of `diff -u`; after all ASTs, `verify` fails and
  suggests rerunning with `DIANA_CLIGHT_UPDATE=1`. With `DIANA_CLIGHT_UPDATE=1` the new AST is
  copied over the committed one and `verify` continues, so the Rocq stage checks the proofs
  against it.
- With no committed AST for the target, it prints that the check is skipped and continues.
- When no AST differs (or each was overwritten), it records the ASTs of the target with
  `script/check_provenance.py --write-manifest <target>` in `verification/clight/manifest.txt`
  (VST-009).
- The check runs before the parallel stages, whatever `DIANA_JOB` is.
