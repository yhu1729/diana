---
id: VST-005
title: VST proofs are per function; no whole-program semax_prog links them
kind: fact
path:
  - verification/rocq/theory/VST/BisectionMid.v
  - verification/rocq/theory/VST/BisectionInit.v
  - verification/rocq/theory/VST/BisectionStep.v
  - verification/rocq/theory/VST/BisectionResult.v
related: [VST-004, VST-006, FP-005, PROOF-007]
---
Each VST theorem is a `semax_body` for one function of one AST, proved under a `Gprog` listing
the funspecs of the functions it calls. No file proves `semax_prog`, so nothing composes the
per-function proofs into a whole-program theorem; each proof assumes its callees' funspecs.

- The only call across source files is from `diana_bisection_init`, `diana_bisection_step` and
  `diana_bisection_result` to `diana_bisection_mid`. Their `Gprog` (built with `with_library`)
  contains `Diana.VST.BisectionMid.mid_spec`, the funspec that BISECTION-C1
  (`body_diana_bisection_mid`) proves of the body in `bisection_mid_aarch64_macos.v`: for any
  floats `a`, `b` it returns `c_mid a b`, that is `Float.mul 0.5 (Float.add a b)`.
- Calls to the `src/fp.h` helpers stay inside one AST, and each copy has its own `semax_body`,
  listed as a theorem of the spec (VST-006).
- The shipped library's object files are joined by the system linker of the gcc or clang build,
  not by CompCert; that the binary behaves as the Clight semantics says is an argument, not a
  theorem (FP-005).
