id: VST-007
title: VST funspecs exclude NULL and malformed-call paths; WP contracts cover them
kind: fact
path:
  - verification/rocq/theory/VST/*.v
related: [VST-005, WP-007, API-002]
---
The VST funspecs relate the C to its model only for well-formed calls: their preconditions
exclude the paths on which a kernel rejects a malformed call with `DIANA_ERR_ARG`, and the NULL
outputs the result functions accept. The ACSL contracts proved by WP cover those paths.

- NULL: every pointer argument is under `data_at` in the `SEP` clause, so it is a valid pointer;
  `diana_bisection_result` and `diana_newton_result` also require `s`, `root` and the second
  output to be non-NULL, so their skip-on-NULL output paths are outside VST.
- Separate `data_at` conjuncts also make the array arguments disjoint.
- Sizes: `1 <= d` for Euler and RK4 (excludes `d = 0`), `n >= 2` for the trapezoidal rule, odd
  `n >= 3` for Simpson.
- RK4 stage number: `2 <= s <= 4` for `diana_rk4_stage` and `diana_rk4_stage_unchecked`.

Not excluded: the value checks (non-finite input or result, `a > b`, a zero derivative, the
iteration limit) are part of the models `c_init`, `c_step` and the array models, which VST proves
for every such exit.

ACSL theorems covering the excluded paths: BISECTION-C2 to C4, EULER-C1, EULER-UNCHECKED-C1,
NEWTON-C1 to C3, RK4-C1, RK4-C2, RK4-UNCHECKED-C1, RK4-UNCHECKED-C2, SIMPSON-C1, TRAPEZOIDAL-C1.
