---
id: VST-008
title: entailer! substitutes a WITH size equal to a list length
kind: fact
path:
  - verification/rocq/theory/VST/ForwardSubstitution.v
  - verification/rocq/theory/VST/BackSubstitution.v
related: [VST-004, VST-007]
---
When a funspec's precondition has `Zlength bl = n` for a WITH variable `n`, VST's `entailer!`
(and `forward` on a `return`, which calls it) runs `subst` and replaces `n` by `Zlength bl` in the
goal it leaves. A later tactic that names `n` then fails with "The variable n was not found".

- `diana_cholesky`'s funspec escapes this: its only length fact is `Zlength al = n * n`, which
  `subst` cannot use.
- The substitution proofs keep tactics after `entailer!` free of `n`: `match goal` patterns with
  `_` (`zeq ?m 0`, `forall i', 0 <= i' < _ -> _`), hypotheses renamed by type
  (`match goal with H : lower_finite _ _ |- _ => rename H into Hlf end`), and the output list
  named with `set (xs := …)` before the `forward` of a `return`, so that `Exists … xs` needs no
  `n`.
- `lt_of_ltu` (`VST/Matrix.v`) needs `n <= Int64.max_unsigned` in context to turn `Int64.ltu`
  loop conditions into `<`; the proofs assert it from `n * n <= Int64.max_unsigned` by `nia`.
