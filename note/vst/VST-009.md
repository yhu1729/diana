title: verification/clight/manifest.txt records the files each AST was checked against

`verification/clight/manifest.txt` has one line `<AST> <SHA-256> <file>` for the AST itself, for
its source and for every repository file the source includes, transitively, sorted by AST and
file. The source is the AST's `Info.source_file`. Names are resolved as `clightgen -Iinclude
-Isrc` resolves them: a quoted name next to the including file, then in `include/`, then in
`src/`, and it must be found; an angle-bracket name in `include/`, then `src/`, and otherwise it is
a toolchain header (`<stddef.h>`, `<float.h>`) and not recorded. An include in a comment or a
disabled `#if` branch also counts, which can only add files.

- Writer: once every AST of the current target matches `clightgen` (or was overwritten under
  `DIANA_CLIGHT_UPDATE=1`), the Clight check of `script/dev.sh verify` (VST-003) runs
  `script/check_provenance.py --write-manifest <target>`. It rewrites the lines of that target's
  ASTs, keeps the lines of other targets' ASTs that still exist, and fails if an AST's
  `Info.source_file` is not `src/<name>.c`.
- Checker: `script/check_provenance.py` without options (CI-016) recomputes the lines of every
  committed `verification/clight/*.v` of any target and fails on a changed hash, a file read but
  not recorded or recorded but no longer read, an AST missing from the manifest, a line for an
  AST that does not exist, or a malformed line.

A line says "this AST was the `clightgen` output for these bytes"; that the VST proofs compile
against the AST is the claim of the report stamp (GATE-009). Commit the manifest with the AST and
the source change that caused it.
