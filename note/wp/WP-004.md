---
id: WP-004
title: How run_frama_c.sh enforces SKIP before it runs WP
kind: fact
path:
  - script/run_frama_c.sh
  - src/bisection_mid.h
related: [WP-003, WP-005]
---
Before WP, `script/run_frama_c.sh` runs `frama-c -metrics` on the same source files with the same
`-cpp-extra-args="-Iinclude -Isrc"` and reads two sections of the metrics report, taking each
function listed there with a non-zero count, that is, each function the sources call. It fails
closed: each section must appear once, as `<title> (N)` over an `===` underline, followed by
entries of the form `name (k call);` or `name (k calls);` that end at a blank line and number
exactly `N`. Otherwise, as after a change of the report format in a Frama-C upgrade, the run stops
with `cannot read the section`.

- "Undefined and unspecified functions": any such function (neither body nor contract) fails the
  run whatever `SKIP` says, because WP would generate a contract for it and assume it.
- "Specified-only functions": a function with a contract but no body fails the run unless its
  name is in `SKIP`, because WP would assume its contract.

An argument that is an existing file is a source; one ending in `.c`, `.h` or `.i` that is not a
file fails the run, and so does a run with no source. Other arguments (`-wp-par 2`) go to WP only.
A failing `frama-c -metrics` prints its output and fails the run.

A `SKIP` entry is also passed to `-wp-skip-fct`, but only for a source on the command line that
has a line starting in column 0 with a return type followed by the name and `(` (the `grep -E` in
the script), because WP rejects that option for a function without a body. No expectation row
names `src/bisection_mid.c` or `src/fp_sqrt.c`, so the normal runs never add the option.

The contracts on the declarations in `src/bisection_mid.h` and `src/fp_sqrt.h` state `terminates
\true` and `exits \false` explicitly; for a function without a body Frama-C would otherwise generate
those clauses itself, with a warning.
