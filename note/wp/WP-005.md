That the rounded midpoint `0.5 * (a + b)` of two finite doubles with `a <= b` and
`|a|, |b| <= DBL_MAX/2` lies in `[a, b]` is beyond what WP's float model and Alt-Ergo prove, so the
computation is the function `diana_bisection_mid`, alone in `src/bisection_mid.c`, and Flocq
proves the fact instead (BISECTION-B1).

- The contract is on the declaration in the private header `src/bisection_mid.h`: `requires`
  finite `a`, `b`, `a <= b` and the bound; `assigns \nothing`;
  `ensures \is_finite(\result) && a <= \result <= b`. The callers see only that declaration, so
  WP assumes the contract at each call (WP-003).
- `src/bisection_mid.c` has no row in `verification/frama-c/expectation.txt` and so no WP goal;
  VST proves its body (BISECTION-C1), and the callers' VST proofs use the funspec that C1 proves
  (VST-005).
- It is an external function in a file of its own, not a `static inline` helper, because three
  sources call it (`src/bisection_init.c`, `src/bisection_step.c`, `src/bisection_result.c`;
  STYLE-002); that also gives it one Clight AST and one VST proof.
