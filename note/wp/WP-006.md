The ACSL predicate `bisection_bracket(s, m)` in `src/bisection_acsl.h` requires
`fa < 0 && fb > 0`, `fa > 0 && fb < 0`, or `a == b && fa == 0 && fb == 0`, together with finite
`a`, `b`, `fa`, `fb`, `a <= b`, `-m <= a`, `b <= m` and `tol >= 0`. The sign part is the
condition `SignChange` of the layer-A models, `f a * f b < 0 or (a = b and f a = 0)`
(`verification/lean/Diana/Real/Bisection.lean`, `verification/rocq/theory/Real/Bisection.v`).

A weak sign change `fa * fb <= 0` is not preserved by the code. `src/bisection_step.c` keeps the
side with `(fx > 0.0) == (s->fa > 0.0)`; with `fa == 0`, `a < b` and `fb < 0`, a step with
`fx < 0` replaces `a, fa` by `x, fx`, and the new bracket has no sign change. The strict form
allows a zero endpoint only once the bracket has collapsed onto it: `diana_bisection_init`
collapses onto a zero `fa` or `fb` and returns `DIANA_OK`.

`bisection_next(s)` (`x` finite and `a < x < b`) is the separate condition under which `step` may
be called; a collapsed bracket never satisfies it.
