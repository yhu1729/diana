WP exits 0 even when goals stay unproved, so its output is always checked by
`script/check_frama_c.sh <output> [<source>]`, and each verified source's goal count is pinned
in `verification/frama-c/expectation.txt`: a changed count means a contract, annotation or RTE
guard appeared or disappeared, and the row changes only when that is intended.

- `expectation.txt` has one `<source> <goal-count>` row per WP-verified file: 22 rows today,
  every verified kernel source except the `SKIP` helpers `src/bisection_mid.c` and
  `src/fp_sqrt.c` (WP-003, WP-005). The source is the path WP runs on and the `acsl` field of
  the matching ACSL theorem in `spec/`.
- `check_frama_c.sh` takes the last `[wp] Proved goals: P / T` line and fails unless it exists
  and `P == T`. Given a source, it also fails unless the file has exactly one row for it with a
  positive count equal to `T`. On the consolidated `report.txt` it would see only the last row,
  so `script/verify_frama_c.sh` runs it on each row's own output (WP-008).
- `script/run_frama_c.sh [option...] [source...]` (default source `src/bisection_init.c`) runs
  `frama-c` with `-cpp-extra-args="-Iinclude -Isrc"`, `-machdep x86_64`, `-warn-special-float
  none`, `-wp -wp-rte`, `-wp-model +float`, `-wp-prover alt-ergo`, `-wp-timeout 30`,
  `-wp-status` and a per-row session and cache (WP-009). Arguments that are not files pass
  through to Frama-C; name the source explicitly when adding an option.
- `-machdep x86_64` is Frama-C 32.1's default, written out because the contracts depend on it
  (WP-015): a 64-bit `size_t`, so the `n·n` overflow guards of the matrix kernels are stated with
  the literal `18446744073709551615`.
- `-warn-special-float none` turns off the alarms on NaN and infinite results, so the RTE goals
  do not include float overflow; finiteness is stated by the contracts (`\is_finite`) and proved
  for the values in Flocq.
- A row's count includes the goals of the `src/fp.h` helpers its source uses, proved per file.
