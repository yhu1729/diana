---
id: WP-010
title: Clear a row's WP cache after a Failed goal caused by a Why3 anomaly
kind: procedure
path:
  - script/run_frama_c.sh
  - script/check_frama_c.sh
related: [WP-009, WP-007]
---
A `Failed` goal whose message is a Why3 error or anomaly, such as
`[Why3 Error] anomaly: Sys_error("No such file or directory")`, rather than a prover answer is an
environment fault. WP 32.1 caches it like any verdict and replays it as `(Cached)`, so clear the
row's cache and rerun the row.

1. Find the row under its `==> src/<row>.c <==` header in `verification/frama-c/report.txt`; the
   row name is the source file name without `.c`.
2. `rm -rf verification/frama-c/cache/<row>`.
3. Rerun the row alone in the opam switch:
   `opam exec -- script/run_frama_c.sh src/<row>.c >"$TMPDIR/<row>.txt" 2>&1`.
4. Check it: `script/check_frama_c.sh "$TMPDIR/<row>.txt" src/<row>.c`.
5. Run `script/verify_frama_c.sh` (or `script/dev.sh verify`) to regenerate the consolidated
   report for all rows.

A `Failed` or `Timeout` verdict that is a genuine Alt-Ergo answer is a proof problem; clearing the
cache does not change it.
