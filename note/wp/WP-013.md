The goal counts of `expectation.txt` (WP-007) and every proof behind them hold for Alt-Ergo 2.6.4,
the version of the toolchain pin (PROVER-001). Another version proves a different set within the
30 s timeout: `framac/frama-c:32.1` ships Alt-Ergo 2.5.4, which timed out on ten goals that 2.6.4
proves in about 2 s at most, two in each of `forward_substitution` and `transpose_substitution`
(the finiteness invariant of `x` and the write of `x[i]`), five memory accesses in `lu` and one in
`lu_solve`.

- `script/check_frama_c.sh` fails a row whose report names an `Alt-Ergo <version>` other than
  2.6.4, before it looks at the counts, so a solver change is reported as such, not as timeouts.
- CI `verify_frama_c` runs `script/fetch_alt_ergo.sh .cache/alt-ergo`, which installs the static
  release binary `alt-ergo-v2.6.4-x86_64-linux-musl` after checking its SHA-256 against the digest
  GitHub publishes for the asset, puts the directory first on `PATH` and runs `why3 config detect`,
  so that WP's Why3 uses it (PROVER-004); the log shows `alt-ergo --version` as `v2.6.4`. Both
  pipelines cache the binary under the hash of the script (CI-026).
- The script refuses any platform but Linux x86-64; locally Alt-Ergo comes from opam (PROVER-002).

A new Alt-Ergo moves together: the version and SHA-256 in `script/fetch_alt_ergo.sh`, the version
in `script/check_frama_c.sh`, the opam install of PROVER-002 and the toolchain table of `CLAUDE.md`;
then rerun every row.
