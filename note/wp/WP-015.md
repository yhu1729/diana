The matrix kernels reject an `n` whose `n·n` does not fit in `size_t` with
`n > (size_t)-1 / n`, which is portable C. Their ACSL contracts state the same guard with the
literal `18446744073709551615`, since ACSL has no `SIZE_MAX`, and `script/run_frama_c.sh` passes
`-machdep x86_64` (Frama-C 32.1's default, 64-bit `size_t` and `long`) so the literal and the
machine model agree. The VST proofs are about the Clight ASTs of the AArch64 macOS target, also
64-bit (VST-009).

So layer C covers a 64-bit `size_t` only. A 32-bit build (`armv7` Linux, `i686`) compiles the
same guard correctly, but no proof describes it; `doc/verification/trust.md` says so. Nothing in
CMake refuses such a build, since the C is correct there and the library makes no claim for it.
